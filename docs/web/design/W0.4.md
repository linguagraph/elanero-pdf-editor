# W0.4: Import audit (what in our Python breaks under Pyodide)

Stage: W0 (#133) · Role: design Opus 5.5, implementation Haiku 5.5, review Sonnet 5.5 · Branch: `phase-w-w0.4-import-audit` · Reuses the W0.1 Pyodide runner (`web/spike/`, PR #144); start after it is merged, and merge `origin/main` first.

## Question this task answers

Which of our modules outside `ui/` import or run under Pyodide unchanged? Which need a change, of what kind, and in which W2 task? The result is the work list for W2.2–W2.6 and closes condition C6 of W0.1 (threads and processes).

## Definitions

- **Web set:** every module under `src/pdfeditor/{model,engine,core,services}` plus `pdfeditor/__init__.py`, `bundle.py` and `licenses.py`, except the **excluded set**.
- **Excluded set** (plan, decision 9): `ui/`, `services/signing/`, `services/ocr.py`, `services/pdfa.py`, `services/store_updates.py`, `services/file_association.py`, `services/export/office.py`, `engine/mupdf/ocr_worker.py`, `selftest.py`, `app.py`, `__main__.py`.
- The list lives in one place: **`web/spike/web_package.py`** (constants `EXCLUDED` and `BLOCKED`, plus a `build_zip(out)` helper that writes the trimmed, deterministic zip without `data/tessdata/` and `__pycache__`). W0.2 uses the same file; whichever task lands first creates it. If this audit finds that a module belongs in the excluded set (or out of it), change the list here and say why in the report.
- **Blocked packages** (unavailable or unwanted on the web): `PySide6`, `shiboken6`, `pikepdf`, `pyhanko`, `pkcs11`, `winrt`, `asn1crypto`, `cryptography`, `numpy`. `numpy` exists in Pyodide but the app doesn't use it (only tests do), so a web-set import of it is a finding.

## Part 1: static scan (host CPython, `ast`, stdlib only)

`web/spike/audit/scan.py` parses every module in the web set and excluded set, and reports per module:

1. Imports of blocked packages, marked **module level** (breaks the import) or **inside a function** (lazy; breaks only when called).
2. Imports or uses of platform features, marked by the same rule:
   - `threading`: separate `Lock`/`RLock`/`Event`/`local`, which work in Pyodide, from `Thread`, `Timer`, `.start()` and `ThreadPoolExecutor`/`concurrent.futures`, which don't;
   - `multiprocessing`, `subprocess`, `os.startfile`, `webbrowser`, `ctypes`, `winreg`, `socket`, `ssl`, `signal`;
   - `urllib.request`, `http.client`;
   - `os.environ` reads (name the variable), `sys.platform`/`os.name` checks, `Path.home()`, `os.getlogin`, `tempfile`.
3. **Import edges into the excluded set:** a web-set module that imports an excluded module (at any level). Any such edge at module level is a must-fix.

Output `out/audit-static.json` and a table in the report.

## Part 2: runtime under Pyodide (Node, the W0.1 runner)

`web/spike/audit/run_audit.mjs` plus `web/spike/audit/audit.py`, which runs inside Pyodide. Setup:
- Load the PyMuPDF wheel, `fonttools` and `pillow` (no `numpy`).
- Mount the trimmed zip, or the source with the excluded set removed from `sys.path` lookups, so an excluded module can't be imported by accident.
- Install a `sys.meta_path` finder that raises `ImportError("blocked on web: <name>")` for the blocked packages.

Then:
1. `importlib.import_module` every web-set module in a **fresh interpreter per module** (or in one interpreter, clearing `sys.modules` of `pdfeditor.*` between modules), so one failure doesn't hide others. Record: ok, `ImportError` (and which name), or another exception (type and message).
2. **Functional checks.** Each is a few lines that call our code, not the library directly:

   | Check | What |
   |---|---|
   | fontTools | `services/fonts`: build a `FontCatalog` over a folder holding one fixture TTF; validate and subset it the way editing does. Also `system_font_dirs()` and `cached_catalog()` (expected: no OS fonts; record what happens) |
   | Pillow | the engine paths that use PIL (e.g. `engine/mupdf/pages.py` image insertion): insert a PNG and a JPEG into a page, and export a page to PNG/JPEG |
   | services/export | run every exporter except `office.py` on a fixture (list them from the registry); record ok, the error, or a missing dependency |
   | threads | `threading.Lock` works; `threading.Thread(...).start()` raises (record the exact error). Run a trivial job through `core/jobs.py` and the render cache in `core/render_cache.py`, and record where each fails |
   | storage | `core/commands/snapshot.py`: a `SnapshotCommand` do/undo round trip on MEMFS (`tempfile`); `core/autosave.py` and `core/secrets.py`: import plus their main entry points, recording what fails (ctypes/DPAPI) |
   | saving | `core/session.py`: `DocumentSession` open from a path on MEMFS, a command, `save()` to a MEMFS path (proves the path API works there; `save_bytes` is W2.3) |
   | translation | `services/translation`: build each client with the default transport and call it with a mocked opener (no network); then without one, recording the failure (`urllib` in Pyodide) |
   | optimize | `services/optimize.reduce_size` on a fixture (expected to fail on the module-level `pikepdf` import; record it) |
3. Write `out/audit-runtime.json`.

Run it in CI as a step of the existing `pyodide-spike` job (cheap, a few seconds), uploading the JSON, and locally.

## The report (`docs/web/spikes/W0.4-results.md`)

One table with a row per web-set module that has a finding:

| Module | Static findings | Runtime result | Fix needed | Task |
|---|---|---|---|---|

The "Task" column is one of: W2.2 (capability flags, lazy imports), W2.3 (bytes, storage, secrets), W2.4 (HTTP transport), W2.5 (jobs without threads), W2.6 (web package/exclusions), "move to excluded set", or "none, works". Below the table:

- a short list of **must-fix before W3** items, and of things that are fine as they are;
- **corrections to the plan** where reality differs. Known example: `services/translation/http.py` already accepts an injectable `opener`, so W2.4 is smaller than planned;
- confirmation that **C6** is closed (where threads and processes are used, and what replaces them).
