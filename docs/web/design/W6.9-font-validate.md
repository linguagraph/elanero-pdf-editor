# W6.9 slice 1: validate an uploaded font (design)

Status: approved and implemented in this PR (slice 1 of W6.9). No storage, UI or docs/guide change.
Scope: slice 1 of W6.9 (plan.md: "W6.9 [I] R1c Font upload"; W1.5 §7; W1.2 §15 items 5 and 6).
This slice adds one read-only call that checks a font file (TTF, OTF, TTC, OTC) with fontTools
and the desktop's embedding rules. It does not store anything: no MEMFS folder, no OPFS, no
catalogue, no UI. Those are the later slices (section 13).

## 2. The call

`fonts.validate` (new namespace `fonts`, as W1.2 §15 item 5 names it). No handle: it touches no
document, so it gives no events and takes no session lock. It calls no MuPDF code, so it does not
need `ENGINE_LOCK` either (AGENTS.md rule 6 is about engine calls).

Deadline class: `action` (30 s), the class W1.2 §10 gives `fonts.add`. Reading the `cmap` of a large
CJK font under Pyodide can take a few seconds, which is past `instant`.

```python
@dataclass(frozen=True, slots=True)
class FontValidateParams:
    name: str    # the file name, for messages and logs only; never a path; 1 to 255 characters
    data: bytes  # the whole file, one $bin buffer

@dataclass(frozen=True, slots=True)
class FontFaceDto:
    index: int                 # face index in the file (0 for a single font)
    family: str                # name ID 16, else 1
    style: str                 # name ID 17, else 2, else "Regular"
    weight: int                # OS/2 usWeightClass (400 without OS/2)
    italic: bool               # fsSelection bit 0 or head.macStyle bit 1
    scripts: tuple[str, ...]   # sorted coarse scripts from the cmap probes ("latin", "cyrillic", ...)
    variable: bool             # has an fvar table

@dataclass(frozen=True, slots=True)
class RefusedFaceDto:
    index: int
    family: str
    style: str
    reason: str                # "restricted" or "bitmap_only" (model.fonts.licence_refusal)

@dataclass(frozen=True, slots=True)
class FontValidateResult:
    format: str                        # "truetype", "opentype" (CFF/CFF2) or "collection"
    faces: tuple[FontFaceDto, ...]     # the usable, embeddable faces; never empty on success
    refused: tuple[RefusedFaceDto, ...]  # faces of a collection that the licence refuses
```

The reply carries no bytes back: the main thread still holds the `File`, and the storage slice
writes it to OPFS from there.

### Error codes

| Code | When | `details` |
|---|---|---|
| `INVALID_ARGS` | `name` empty or longer than 255 characters; `data` missing or not a buffer (from `from_json`); an unused buffer | `{path}` |
| `FILE_TOO_LARGE` | `len(data) > limits.MAX_FONT_BYTES`, checked **before** any parsing | `{max_bytes, size}` (W1.2 §4 convention; `rpc/errors.ts` already reads `max_bytes`) |
| `INVALID_FONT` | not an sfnt or collection (wrong magic, empty file, WOFF/WOFF2, Type 1, `.dfont`); fontTools fails on the header or a needed table; a collection with more than `MAX_COLLECTION_FACES` faces; no usable face | `{reason}`: `not_a_font`, `woff`, `unreadable`, `too_many_faces`, `no_usable_face` |
| `FONT_NOT_EMBEDDABLE` | at least one face is usable, and every usable face is refused by its fsType | `{reason}` of face 0 of the refused list (`restricted` or `bitmap_only`), `{faces}` the count |
| `NOT_SUPPORTED` | fontTools can't be imported (the web worker did not install it) | none |
| `OUT_OF_MEMORY` | a `MemoryError` while parsing (the existing mapping; the service must re-raise `MemoryError`, not turn it into `INVALID_FONT`) | none |

A file with both unreadable faces and refused faces is `FONT_NOT_EMBEDDABLE` when no face is usable
and embeddable but some face is usable: the licence is the more useful message.

The `reason` strings are stable codes for the front end's messages, never English text, and never
a traceback or font content.

## 3. Service function (reuse and new)

In `services/fonts.py` (now shipped on the web):

```python
class FontRejected(Exception):
    """A font file that can't be added. ``kind`` is "invalid" or "not_embeddable"."""
    kind: str; reason: str; refused: list[FontFace]

def validate_font_bytes(data: bytes, label: str) -> tuple[str, list[FontFace], list[FontFace]]:
    """(format, embeddable faces, refused faces) of an uploaded file, or FontRejected."""
```

**Reused:** `_face_from_ttfont` (all face fields, `embeddable`, `reason`), `_embeddable`,
`_script_coverage`, `_name`, and the model's `RESTRICTED`/`BITMAP_ONLY`/`licence_refusal`. The
desktop's catalogue path (`read_faces`, `scan`, cache format) is unchanged.

**New:**
1. Magic sniffing before fontTools: `00 01 00 00` or `true` (TrueType), `OTTO` (CFF), `ttcf`
   (collection). `wOFF`/`wOF2` give `woff`; anything else gives `not_a_font`.
2. For `ttcf`, read `numFonts` from the 12-byte header with `struct` and refuse more than
   `MAX_COLLECTION_FACES = 64` before `TTCollection` reads the offset table. Real collections have
   at most a few dozen faces; a forged header could otherwise make fontTools build a million
   offsets.
3. A usable-face check on top of `_face_from_ttfont`'s "has a family name": the face has a Unicode
   `cmap` with at least one mapping, and outlines (`glyf` with `loca`, or `CFF `, or `CFF2`, checked
   in the table directory only). A colour-bitmap-only font (sbix, CBDT) has no outlines and can't
   be embedded as a PDF font, so it is `no_usable_face` now rather than an edit failure later.
4. Error classification: `read_faces` swallows every exception; the new function catches
   `Exception` per face (an unreadable face is skipped) and for the header (`unreadable`), but lets
   `MemoryError` through.
5. Lazy imports: `from fontTools.ttLib import TTFont` and `TTCollection` move inside the functions;
   annotations use `TYPE_CHECKING`. The module then imports under Pyodide before fontTools is
   installed, and `validate_font_bytes` raises `ImportError`, which the webapi maps to
   `NOT_SUPPORTED`.

The webapi side is a new `webapi/fonts.py` (`validate(params) -> FontValidateResult`), mapping
`FontRejected` to `RpcFailure` locally, as `actions.xfdf_preview` does with `XfdfTooLarge`. The
mapping is not added to `errors._MAPPING`: these exceptions are only raised by this call.

## 4. Size limit

`webapi/limits.py`: `MAX_FONT_BYTES = 50 * 1024 * 1024` (50 MiB), the value W1.5 §7 chose.

Why 50 MiB: it takes every single-weight font in common use, including the big ones (Noto Sans CJK
per-weight collections are about 20 MB, Arial Unicode about 23 MB), and refuses only the
multi-weight "super" collections (over 100 MB), which a user can replace with the single weight
they need. The bound matters because the bytes are held in the worker's heap more than once (the
transferred buffer, the Python `bytes`, the copy MuPDF makes when it embeds), the worker heap warns
at 1.5 GiB (`HEAP_WARN_BYTES`), and OPFS storage is shared with autosave. The constant sits in
`limits.py` so tests can monkeypatch it, like the other limits. The main thread checks the same
number before sending (UI slice); the worker check stays, since the worker never trusts the caller.

## 5. Reading only the tables needed

`TTFont(BytesIO(data), lazy=True, fontNumber=0)` for a single font and
`TTCollection(BytesIO(data), lazy=True)` for a collection. With `lazy=True` fontTools reads the table
directory and decompiles a table only on first access. The tables touched:

- decompiled: `name`, `OS/2`, `head`, `cmap` (through `getBestCmap`, which also loads the glyph order:
  `post` for TrueType, the `CFF ` charset for CFF);
- directory only (`tag in font`): `fvar`, `glyf`, `loca`, `CFF `, `CFF2`;
- never touched: `glyf`/`CFF ` charstrings, `GSUB`, `GPOS`, `hmtx`, `kern` and the rest.

Each font and the collection are closed in `finally`. A test asserts `font.isLoaded("glyf")` is
false after validation, so a later change can't quietly decompile outlines.

## 6. Collections (TTC/OTC)

- Every face is read, in order, up to `MAX_COLLECTION_FACES`.
- A face that can't be read or isn't usable (section 3, point 3) is skipped.
- A usable face whose fsType refuses embedding goes to `refused`.
- The file is accepted when at least one face is usable and embeddable. `faces` lists those;
  `refused` lists the rest, so the UI can say "2 of 4 faces can't be used" (question 4).
- `format` is `collection` whatever the outlines; an OTC (CFF in a collection) is the same case.
- Index numbers are the file's own, so the storage slice can keep `FontRef.file(path, index)` as is
  (`engine/mupdf/content.py:_extract_face` splits the face out at embed time, and re-checks fsType).

## 7. fsType rules (exactly the desktop's)

The OS/2 `fsType` bits, as `_embeddable` and `model.fonts.licence_refusal` read them:

| fsType value | Meaning | Result |
|---|---|---|
| `0x0000` | Installable | accepted |
| `0x0004` | Preview and print | accepted |
| `0x0008` | Editable | accepted |
| `0x0100` | No subsetting | accepted (the desktop ignores it, though MuPDF subsets on save: question 3) |
| any value with bit `0x0002` set (`0x0002`, `0x0006`, `0x000A`, `0x0202`, ...) | Restricted licence | **refused**, `restricted` |
| any value with bit `0x0200` set and `0x0002` clear (`0x0200`, `0x0204`, ...) | Bitmap embedding only | **refused**, `bitmap_only` |
| no OS/2 table | (some old Mac fonts) | accepted |

Restricted is named first, so `0x0202` reports `restricted`. Other bits (reserved, 0x0001) are ignored.
The OpenType spec says that for OS/2 versions 0 to 2 the least restrictive of several set bits
wins (so `0x0006` would be preview-and-print); the desktop refuses it, and W1.5 §7 says "the web
adds nothing", so the web refuses it too (question 3).

## 10. Frozen build

- fontTools is a core dependency and is already in `Elanero.exe`. PyInstaller finds imports inside
  function bodies, so making the imports lazy does not drop the module. The table modules this
  slice decompiles (`name`, `OS/2`, `head`, `cmap`, `post`, and `CFF ` for OTF) are the ones the
  desktop catalogue and PDF/A code already load frozen (`services/pdfa.py` imports `cffLib`).
- `fontTools` is not in `DEV_EXCLUDES`, and no new package is added, so nothing in the spec changes.
- The desktop does not call `validate_font_bytes` (webapi is not imported by the app). The self-test's
  existing `fonts` and font-catalog checks exercise the moved lazy imports frozen, so `selftest.py`
  needs no new check. Before the PR: `uv run python scripts/build_exe.py --test` ends with `RESULT: OK`
  (CI runs the same on code PRs).
- If a frozen run ever fails on a table module, the fix is `collect_submodules("fontTools.ttLib.tables")`
  in `hiddenimports`; not expected, since the same tables already load.

## 13. Risks

1. **Shipping `services/fonts.py`** adds its imports (`core.jobs`, `core.paths`, `model.platform`) to
   the web package. All are already shipped, and the W0.4 audit (`web/spike/audit/audit.py`) already
   imports the module under Pyodide for its `fonts.validate` and `fonts.scan` checks (check the latest
   audit result before relying on it). The package grows by the module's source, about 20 KB.
2. **fontTools not yet installed in the worker.** `needsFontTools` only looks at `actions.run`. Until
   the web slice adds `fonts.validate`/`fonts.add` to it, a front-end call would get `NOT_SUPPORTED`.
   No front end calls it in this slice.
3. **Slow `cmap` on large CJK fonts under Pyodide** (format 12 with 30,000+ mappings). Measured in the
   web slice; the `action` deadline (30 s) leaves room, and the call is off the main thread.
4. **Hostile input.** fontTools is pure Python, so a bad file can raise or be slow but can't corrupt
   memory. The size cap, the collection face cap and the lazy reading bound the work; every exception
   but `MemoryError` becomes `INVALID_FONT`.
5. **CFF2 (variable OTF).** Accepted here, as the desktop accepts it. If MuPDF can't embed a given
   CFF2 face, the failure shows at edit time; the web slice's Playwright test should use a TTF.
6. **Parity drift.** The fsType rules stay in `_embeddable` and `licence_refusal`; this slice adds no
   third copy, and a test runs the same fixtures through both.
7. **The usable-face check is stricter than the desktop catalogue** (it needs outlines and a non-empty
   cmap). A font the desktop lists could be refused on the web. That is a deliberate improvement for
   uploads; the desktop catalogue is unchanged.

## 14. What the later slices need

**S2: worker storage and catalogue.**
- `fonts.add {name, data}` (W1.2 §15 item 5) = `validate_font_bytes`, then write to a MEMFS folder
  (`/fonts/`) under a content name, `sha256(data)` plus the extension from the magic, never the user's
  name (no path tricks, and a re-upload is a no-op). Returns the faces with an opaque `id`.
- `FontCatalog(folders=[upload folder], cache_path=None or a MEMFS file)`, rescanned after add/remove.
- `fonts.list`, `fonts.remove {id}` (W1.5 says `id`, W1.2 says name: settle on `id`).
- Actions accept a `FILE` ref only inside the upload folder (`INVALID_ARGS` otherwise, W1.5 §7).
- `loader.ts`: `needsFontTools` also true for `fonts.add` and `fonts.validate`.
- Jobs: the job worker has its own MEMFS. A job that typesets with an uploaded font needs the font
  bytes sent along (or the job refuses `FILE` refs). Check which jobs can reach text typesetting.

**S3: OPFS persistence and start-up load.**
- The main thread writes the file to OPFS `/fonts/` after `fonts.add` succeeds (W1.1 §6), and
  deletes it on remove and on "Remove all fonts" and clear-site-data (W1.1 answer 2).
- At start-up, and after **every engine restart** (a cancelled job discards the worker, decision 5,
  so MEMFS is lost), the main thread re-sends each stored font with `fonts.add`; the viewer doesn't
  wait. A stored font that now fails validation is removed with a notice.
- A total budget across fonts (and an OPFS quota error), and other tabs: each tab's worker loads its
  own copy; a remove is broadcast (BroadcastChannel) so other tabs drop it.

**S4: UI.**
- "Upload font…" in Preferences ▸ Fonts and in the font picker (W6.8b's "Uploaded" section); file
  input `accept=".ttf,.otf,.ttc,.otc"`; main-thread size check with the same 50 MiB (export
  `MAX_FONT_BYTES` through `generated.ts` instead of a hand-copied number, unlike `openFile.ts`).
- The success, partial-collection and error messages of section 11; the list with Remove and
  Remove all and their confirmations; keyboard and screen-reader access.
- Vitest with a fake RPC client; Playwright on three browsers: upload a font, use it in Add Text,
  save, reopen and check the text (the round-trip rule, with pikepdf and pypdfium2 host checks of the
  embedded font); upload a restricted font and see the refusal.
- `docs/guide/` page for fonts on the web.

## Questions for the maintainer

1. **Call name for this slice.** `fonts.validate` (read-only, kept; S2's `fonts.add` calls the same
   service function) or `fonts.add` now with no storage? **Recommended: `fonts.validate`.** A
   `fonts.add` that adds nothing would mislead; if nothing in the web app calls `fonts.validate` after
   S4, S4 removes it.
2. **Where the checks live.** Ship `services/fonts.py` on the web with lazy fontTools imports, or move
   the face-reading helpers into a new shipped module and keep the catalogue excluded?
   **Recommended: ship `services/fonts.py`.** S2 needs `FontCatalog` on the web anyway (W1.5 §7), and
   one module keeps one copy of the rules.
3. **fsType parity.** Keep the desktop's rule (refuse whenever `0x0002` or `0x0200` is set, even with
   `0x0004`/`0x0008` also set; ignore `0x0100` no-subsetting although MuPDF subsets)? **Recommended:
   keep parity now.** Any change applies to both apps and belongs in its own issue.
4. **Collections with some refused faces.** Accept the file and list the refused faces, or refuse the
   whole file? **Recommended: accept** and show "n of m faces can't be used"; the embed path re-checks
   each face anyway.
5. **Size limit.** 50 MiB per file (W1.5 §7), with a total budget decided in S3? **Recommended: yes.**
6. **WOFF and WOFF2.** Refuse with `INVALID_FONT` (`woff`), or convert? **Recommended: refuse.** WOFF2
