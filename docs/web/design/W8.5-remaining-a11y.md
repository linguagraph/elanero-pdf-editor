## 2. Design

### 2.1 Reduced motion: honour the preference, and one global rule

- New `web/app/src/theme/motion.ts`: `applyReduceMotion(on, root = document.documentElement)` sets
  or removes `data-reduce-motion="true"`; `initReduceMotion()` reads `readPreferences().reduceMotion`
  and applies it. Same shape as `theme/accent.ts:14-28`.
- `main.tsx` calls `initReduceMotion()` beside `initAccent()` (line 64), before the first render.
- `PreferencesDialog.tsx`: the checkbox previews at once, like the accent (`chooseAccent`, line 219),
  and Cancel restores the saved value where the accent is restored (line 122).
- New `web/app/src/theme/motion.css`, imported once in `main.tsx` after `tokens.css`. One rule set,
  under two selectors, for every element including portaled dialogs:

  ```css
  @media (prefers-reduced-motion: reduce) { *, *::before, *::after { /* the four lines */ } }
  :root[data-reduce-motion='true'] *, :root[data-reduce-motion='true'] *::before, … { … }
  ```

  The four declarations: `transition-duration: 0s !important; animation-duration: 0s !important;
  animation-iteration-count: 1 !important; scroll-behavior: auto !important;`.
- The three per-file blocks stay (they are what `motion.test.ts` checks), and each gains the
  `:root[data-reduce-motion='true']` selector beside its media query, so the per-file rule holds for
  the preference too. `motion.test.ts` learns the second selector.
- No new colour or size token: motion has no token today, and `0s` is not a design value.
- JS motion: none to change. The `requestAnimationFrame` loops (`useTextSelection.ts:144`,
  `useReorderDrag.ts:155`, `useOutlineDrag.ts:200`) follow the pointer during a drag, which W5.2's
  note already ruled is not animation (`W5.2-drag-drop.md:215`); `FontPicker.tsx:54` scrolls without
  `behavior: 'smooth'`.
- Guide: `web-accessibility.md:51-54` says the switch now works, either way round (the system
  setting or the switch).

### 2.2 Touch targets: a token, the missing controls, and a sweep

- Token: `TOUCH_TARGET_PX = 44` in `web/app/src/theme/tokens.ts` beside `LAYOUT_PX` (line 104), and
  `tokens-css.ts` writes `--size-touch-target: 44px`. Regenerate with `npm run tokens`; never edit
  `tokens.css` by hand. New rules use the token; the existing literals stay (changing 25 files buys
  nothing, and `touchAndForced.test.ts` parses px). The test's `px()` learns to resolve
  `var(--size-touch-target)` from `tokens.ts`.
- Coarse-pointer rules (`@media (pointer: coarse)`, `min-width` and `min-height` of the token), each
  in the component's own stylesheet:
  - `ribbon.css`: `.app-menu-item` (and the ribbon's other menus' items, if they use another class).
  - `tabs.css`: the items of the tablet drop-down (`DocumentTabMenu`).
  - `edit/edit.css`: `.edit-style-bar button, input, select`; `.edit-font-option`.
  - `theme/ThemeSwitch.css`: `.theme-switch-option`.
  - `app.css`: `.update-banner button`.
  - `combine.css`, `properties.css`, `security.css`, `translate.css`, `links.css`: their buttons,
    text fields and selects (`.combine-button`, `.combine-pages input`, `.properties-button`,
    `.properties-field input`, `.properties-tab`, `.security-field select`, `.security-check`, the
    translate bubble's select, the link dialog's buttons).
  - Whatever else the sweep below finds.
- Not a target: the text-layer spans (selection is by drag; the handles are already 44 px,
  `textLayer.css:52-55`), `.edit-handle` (visual only, `pointer-events: none`, `edit.css:37-42`;
  its hit area is computed in JS, check it in review), inline links inside running text (WCAG 2.5.8
  inline exception).
- 44 px is the project's own bar (W1.6.md:195, WCAG 2.5.5 AAA). WCAG 2.2 AA (2.5.8) asks for 24 px,
  so a gap here is a project bug, not an AA failure; the guide keeps saying 44.
- Guide: `web-accessibility.md:57-60` drops "Other controls are not yet held to that size" and lists
  the exceptions.

### 2.3 Axe coverage: side panels, ribbon tabs, engine dialogs; the tab strip fixed

- New `e2e/features/a11y-panels.spec.ts`, engine staged, both schemes: open `text_multipage.pdf`
  (and `outline.pdf` for bookmarks, the comments fixture for comments, a layered fixture for layers,
  an attachment fixture for attachments; all exist for the W8.1 specs), open each of the 8 panels
  from its rail button, `checkAxe`; then click each of the 7 ribbon tabs and `checkAxe`. One test per
  panel and per tab, so a failure names the screen.
- The same spec opens the engine dialogs the jsdom checks cover, now in the browser for contrast:
  Save As, Print, Export, Compress, Split, Combine, Properties, Security, Flatten, Mark Text. One test
  each, reusing the openers of the W8.1 specs (`support.ts`).
- The tab strip: remove `KNOWN_TAB_ISSUES` by fixing the markup (question 1). Recommended shape, in
  `tabs/DocumentTabs.tsx`:
  - Keep react-aria `Tabs`/`TabList`/`Tab` for roving focus and selection.
  - react-aria points each tab's `aria-controls` at a `TabPanel` that the strip never renders.
    Give the tabs one real target instead: the document view gains `id="document-view"`, and the
    selected tab passes `aria-controls="document-view"` (the others none). Empty hidden panels are
    not used: they would put one empty `tabpanel` per open document in the tree. If react-aria overrides an
    explicit `aria-controls`, wrap the document view in a single `TabPanel` instead. The implementer
    decides with a spike test first; either way is under 40 lines.
  - Move the close control out of the accessibility tree of the tab: the `×` becomes a non-focusable
    `<span aria-hidden="true" class="doc-tab-close">` with a pointer handler (mouse and touch), and the
    keyboard closes the focused tab with Delete and with the existing Ctrl+W command. The tab gets
    `aria-keyshortcuts="Delete"` and its accessible description says "Press Delete to close"
    (`t('tabs.closeHint')`, new key in `en.ts`). The tablet drop-down (`DocumentTabMenu`) already
    has its own close item and is unchanged.
  - Touch: the span keeps the 44 px coarse rule (`tabs.css:115-117`).
- Then `axe.ts` loses `KnownIssue` handling for the tabs (keep the mechanism, empty list), and
  `document.spec.ts:28` and `links.spec.ts:142,146` stop passing `KNOWN_TAB_ISSUES`.

## 5. Risks

- **Touch rules growing layouts.** A 44 px menu item or dialog field makes the ribbon's compact
  mode and narrow dialogs taller under touch. Mitigation: only under `pointer: coarse`; the existing
  `ribbon.spec.ts` and `layout.spec.ts` geometry checks run under a fine pointer and stay green; the
  sweep's screenshots are attached for review.
- **The global motion rule hides a needed transition.** A component that waits for `transitionend`
  would never get it with `0s`. Nothing waits for one today (no `transitionend` or `animationend`
  listener in `src`); the reviewer greps for it.
- **react-aria and `aria-controls`.** If `Tab` ignores an explicit `aria-controls`, S8 needs the
  `TabPanel` route, which puts the document view inside `Tabs`; that moves the strip and the view
  into one component tree. The S8 spike test decides before the rest is written.
- **Removing the focusable close button** changes how keyboard users close a tab. Delete and Ctrl+W
  cover it, and the description announces it, but it is a behaviour change: owner decision
  (question 1).
- **web-a11y needs a warm wheel cache.** Like web-e2e, it stops on a cache miss; the run in S10
  first dispatches `web-pytest.yml` on main if the cache is cold.
- **New panel axe findings.** S9 may find more than 200 lines of fixes (contrast in a panel, a
  missing name). Then S9 lands the spec with the failing tests marked `test.fixme` naming an issue,
  and each fix is its own small PR; S10 waits for them.
- **A green run is a snapshot.** web-a11y is on demand only, so a later regression is caught by the
  nightly web-e2e (which runs the same specs), not by a required check.
