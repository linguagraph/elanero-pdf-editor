**Defects found while verifying** (fixed in the slices below, not here):

1. `en.ts:1413` `'marks.hf.tokens'` lists `{page}`, `{pages}`, … The engine's tokens are `<<page>>`, `<<pages>>`, `<<label>>`, `<<date>>`, `<<file>>`, `<<bates>>` (`stamping.py:27-28`). ## 2. The desktop behaviour each dialog must match

### 2.1 The flow around every mark dialog (`ui/organize.py`)

- Four ribbon buttons, Header & Footer, Bates Numbering, Watermark and Background (`organize.py:108-111`). Each has a menu: **Add…**, **Update…**, **Remove** (`organize.py:112-148`).
- **Add** with marks of that kind already there: a question "This document already has {phrase} (pages {ranges}). Replace it with the new one, or add the new one as well?" with **Replace Existing** (default), **Add New** and Cancel (`organize.py:445-462`). Replace opens the dialog as an Update; Add New opens it empty (`organize.py:464-478`).
- **Update** with none: "This document has no {kind} added by this app or Acrobat to update." (`organize.py:468-474`).
- **Update** (or Replace): the title becomes "Update {name}"; the dialog loads the stored settings and preselects the pages the marks are on (`organize.py:480-494`). Marks found only from another tool (`foreign`): the subtitle says "Replaces the one another application added (its settings can't be read)." (`organize.py:488-492`).
- **Remove**: no confirmation. With none: "This document has no {kind} … to remove." With some: one undo step and a toast "Removed {kind} from {n} page(s)." with Undo (`organize.py:605-624`).
- Every Add and Update is one undo step, labelled by `marks.py:65-67`.

## 3. Engine side: what is new

### 3.1 `marks.get` (new, instant, read-only)

`marks.list` keeps its shape. A new method returns what an Update needs:

```
marks.get(handle, kind: MarkKind) -> MarkDetailResult
  found: bool                 # false: no mark of this kind
  pages: tuple[int, ...]      # 0-based, ascending (find_marks' list)
  ranges: str                 # services.pages.format_page_ranges(pages), 1-based text for the range field
  foreign: bool
  header_footer: HeaderFooterSpecDto | None   # kind HeaderFooter or Bates, settings readable
  watermark: WatermarkSpecDto | None          # kind Watermark
  background: BackgroundSpecDto | None        # kind Background
  font_dropped: bool          # the stored spec used an uploaded font (FILE ref): shown as Helvetica-family base-14, with a note
```

It calls `stamping.find_marks(..., [kind])` and the matching `*_from_settings` reader under `session.lock`, and turns the spec into a DTO (colour as `{r,g,b}`, slots by their `Slot.value`). A `FILE` font ref is replaced by the base-14 code the spec already carries (`spec.font`, which the desktop sets from the family, `pages.py:70-76`) and sets `font_dropped`. A `DOCUMENT` or `STANDARD` ref is mapped the same way. `format_page_ranges` is `services/pages.py:99`, reused so the range text matches the desktop's. The DTOs live in `webapi/dto.py`; `web/app/src/rpc/generated.ts` is regenerated (`python scripts/make_web_types.py`). Deadline `instant`, as `marks.list` (`generated.ts:1049`).

### 3.2 Builder fixes in `marks.ts`

Defects 2 and 3 of §1: Bates fields always sent; `canRunWatermark`, `canRunBackground`, `canRunHeaderFooter` use the desktop ranges, kept as named constants beside the builders (`MARK_LIMITS`). One `marginY` form field feeds `margin_top` and `margin_bottom` (question 6). `fromMarkDetail(detail)` turns a `marks.get` reply into the dialog's form.

### 3.3 Image watermark

- Python: no change to the action. `Watermark.image: bytes | None` already converts from a `$bin` buffer through `from_json`. `_convert_action` gains a per-action argument check for `marks.watermark`: the image, if any, must be PNG or JPEG (`custom_stamps.image_size(data) is not None`) and at most `limits.MAX_IMAGE_BYTES` (50 MiB, `webapi/limits.py:62`), else `INVALID_ARGS` with path `args.args.spec.image`. `image_path` is the file's name only (the web has no path).
- Web: `runActionJob` takes an optional `buffers: readonly ArrayBuffer[]` and an `args` that already holds `$bin` markers numbered from 1, so `job.run` sends `[document, ...buffers]`. `jobs.prepare` receives its own **copy** of each buffer, since the RPC client transfers (detaches) what it sends (`rpc/client.ts:121`).
- Update of an image watermark: the stored settings have no picture (`stamping.py:359-361`). The dialog loads the other settings, selects Image, shows the old file name, and asks for the picture again (`marks.wm.imageAgain`); Apply stays refused until one is chosen. This matches the desktop's behaviour when the file has moved (`spec()` raises `OSError`, `pages.py:573-575`).

### 3.4 Stamp in `annotations.create`

`CommentTool.STAMP = "stamp"` (`comment_tools.py:77`), a `stamp: str = ""` field on `CreateAnnotation` (checked against `STANDARD_STAMPS`, else `Refused`), undo label "Add Stamp", and a `build_stamp(page, center, name, author)` builder that makes the desktop's 160 × 50 pt model with `icon = name` and `DEFAULT_STYLES[STAMP]` (`actions/comments.py:81`). The desktop `StampTool` is then refactored to call `build_stamp` for standard stamps, so the logic exists once (plan "Reuse principle"). The rect is clipped to the page as the other tools do (`comment_tools.py:104-110`); a click whose box is wholly off the page does nothing.

`AddAnnotationCommand` is the command: a real inverse, not a snapshot.

## 5. The web UI

All dialogs use `layout/Overlay` (react-aria `Modal` and `Dialog`: focus is trapped, Escape closes, focus returns to the button that opened it) and run their action with `runMark` (an action job: the job bar shows progress and Cancel; the dialog closes when the job starts, as Flatten does, `flatten/FlattenDialog.tsx:1-5`). A finished job redraws the changed pages (`onChanged`) and offers Undo in a toast (`feedback/undoToast.ts:24`, as `crop/runCrop.ts:36`). A failure goes through `reportActionError` (`actionJob/errors`), with `marks.failed` as the fallback.

### 5.1 Shared shell (`marks/MarkDialog.tsx`)

- **Opening.** Each of the four commands (`catalog.ts:232-235`) opens its dialog from `App.tsx`'s handler map. The command needs an open document; the dialog is not offered without `page_ops` (the commands are disabled, as other page commands are).
- **Step 1: existing marks.** On open the shell calls `marks.get(kind)` (`marks.loading` while it reads). With `found: false` it goes straight to the form with defaults. With marks, it shows the desktop's question in the dialog: `marks.existing` ("This document already has {kind} on {count} pages.") followed by the ranges, and three buttons, **Replace** (`marks.replace`, default and focused), **Add New** (`marks.addNew`), **Remove** (`marks.remove`), plus Cancel. Replace = the desktop's Update; Add New = a fresh form; Remove = the desktop's Remove with no further question. This folds the desktop's Add/Update/Remove menu into one place, since the web commands have no split-button menu (question 1).
- **Replace** loads the form with `fromMarkDetail`, sets the title to `marks.update.title` ("Update {name}"), and preselects the scope: All when the pages are all pages, Current when they are the current page, else Pages with `ranges` filled in (as `PageRangeBox.select_pages`, `pages.py:130-139`). With `foreign`, the note `marks.foreignNote` shows; with `font_dropped`, `marks.fontDroppedNote`.
- **Page scope.** Three radios, All pages / Current page / Pages with a range field, read by `markPages` (`marks.ts:108-117`, the print dialog's rules). An invalid range shows `marks.scope.rangeInvalid` in a `role="alert"` paragraph, with `aria-invalid` and `aria-describedby` on the field, as `PrintDialog.tsx:166-181`.
- **Signed document.** A note (`marks.signedNote`) as in Crop (`CropDialog.tsx:180`); the action still runs (question 8).
- **Footer.** Apply (`marks.apply`, the form's submit, so Enter applies) and Cancel (`marks.cancel`). Apply is disabled while `canRun*` is false, and a one-line reason is shown in a polite live region next to it, so the reason is announced and not only implied by a greyed button.
- **Remove.** Runs `marks.remove`; the toast is `marks.done.removed` (plural, count = pages from `marks.get`) with Undo.

### 5.2 Background dialog

Title `marks.bg.title`; colour (`<input type="color">`, labelled `marks.color`), opacity as a number field 5–100 with a `%` suffix (`marks.opacity`), scope. Defaults #ffffe6 (1, 1, 0.9) and 100.

### 5.3 Header & Footer and Bates dialog

One component with a `bates` prop. Title `marks.hf.title` or `marks.bates.title`. A grid of six text fields: column headers `marks.hf.left|center|right`, row headers `marks.hf.header|footer`; each field has its own accessible name (`marks.hf.slot`, "{row} {column}", e.g. "Footer right"), and the grid is a `role="group"` labelled by the dialog's subtitle. The tokens help (`marks.hf.tokens`, fixed text) is linked to every slot with `aria-describedby`. Bates mode pre-fills Footer right with `<<bates>>`.

"Text style" is a `<details>` (collapsed, as the desktop's section): font select (`MARK_FONTS`), size, colour, side margin, top/bottom margin. "Bates number" is a `<details>` open in Bates mode, closed otherwise: prefix, start, digits, suffix, plus a live preview line `marks.bates.preview` ("First number: {value}") computed as `bates_number` does (`stamping.py:57-59`). `<details>`/`<summary>` is keyboard-operable and announced as expanded/collapsed without extra ARIA.

### 5.4 Watermark dialog

Title `marks.wm.title`. A radio group Text / Image (`marks.wm.useText`, `marks.wm.useImage`). Text: the text field (`marks.wm.text`), default "CONFIDENTIAL". Image (slice S5): a file button (`marks.wm.chooseImage`, `accept="image/png,image/jpeg"`), the chosen file's name, and `marks.wm.imageAgain` on an Update. Appearance: font, size, colour, opacity 5–100 (default 30), rotation −180–180 (`marks.wm.angle`, default 45, disabled for an image), image size 5–100 % of page width (`marks.wm.scale`, disabled for text), and the checkbox "Behind page content" (`marks.wm.behind`, replacing `marks.wm.onTop`).

### 5.5 Stamp tool (slice S6)

The `stamp` command (`catalog.ts:292`) opens a menu button (react-aria `MenuTrigger`/`Menu`: arrow keys move, Enter chooses, typeahead by label, Escape closes) with the 14 standard stamps (`stamp.name.<Name>` keys, in `STANDARD_STAMPS` order). Choosing one makes it the active comment tool (`state.commentTool === 'stamp'`, `checked` in the catalogue as other tools). A click on a page sends `annotations.create` with `tool: 'stamp'`, `stamp`, and the click point as a zero-size rect. Keyboard: with the tool active and a page focused, Enter places the stamp at the centre of the visible part of the page (proposed here, so the tool is usable without a pointer; the W7.1a tools have no keyboard placement yet). After placing, the live region says `stamp.placed` ("{name} stamp added on page {page}.") and Undo is offered.

## 8. Edge cases

- **Busy document.** The mark actions call `ensure_idle`; `jobs.prepare` refuses with `BUSY` while another job runs, and the shell reports it through `reportActionError`.
- **Cancel during the job.** The job worker is terminated and the document is unchanged (`actionJob.ts:141-150`); no toast.
- **A no-op job.** Blank slots or no pages would still apply a copied document and record an undo step (`marks.ts:6-7`); the `canRun*` checks keep such a job from starting.
- **`<<date>>`.** It uses `date.today()` in the job worker (`stamping.py:75`). The time zone Pyodide reports in a browser worker is not verified here; the tests assert the date format, not the day.
- **`<<file>>`.** The tab's display name, as the desktop uses `session.display_name` (`organize.py:532`).
- **Fonts.** Base-14 only on the web (§1, jobs refuse `FILE` refs). A stored desktop spec with an uploaded font loads with `font_dropped` and its base-14 family.
- **Large documents.** Marks run in the job worker on a copy, within `MAX_JOB_BYTES` (`limits.py:33`); the heap warning already runs (`actionJob.ts:131`).

## 9. Questions for the owner

1. **Existing marks: one dialog step instead of the desktop's split-button menu and message box?** The web commands are plain buttons. Recommended: yes, the dialog opens on a "This document already has …" step with Replace (default), Add New, Remove and Cancel; the desktop keeps its menu.
2. **Uploaded fonts in marks.** Jobs refuse `FILE` font refs (the job worker has none). Recommended: base-14 only in W7.3; sending font bytes to the job worker is a separate follow-up if users ask.
3. **Image watermark formats.** The desktop file filter offers PDF, TIFF, BMP, GIF and WebP too, though at opacity below 1 only what PIL reads works and a PDF fails. Recommended: PNG and JPEG on the web (the custom-stamp rule, `custom_stamps.image_size`), at most 50 MiB.
4. **Updating an image watermark.** The stored settings have no picture. Recommended: load the other settings and ask for the picture again (Apply refused until chosen), rather than storing the picture's bytes in the settings JSON.
5. **Custom image stamps (S7): in W7.3 or later?** They need a persistent OPFS library on the web. Recommended: standard stamps in W7.3 (S6), custom stamps as a follow-up item (W7.3b), so W7.3 can be ticked after S6.
6. **One "Top/bottom margin" field (as the desktop) or two?** The catalogue has two keys. Recommended: one field, as the desktop, feeding both values; drop the two keys.
7. **"Selected pages" in the page scope.** The desktop offers it when more than one page is selected. Recommended: not in W7.3 (the web dialogs follow the print dialog's three choices); add it with the organizer's selection later if wanted.
8. **Signed documents.** Marks rewrite page content, so signatures will show a change. Recommended: allow it with a note, as Crop and Flatten do.
