## 2. Services on the web

|---|---|---|---|---|
| MyMemory (default) | `https://api.mymemory.translated.net/get` (GET) | nothing | none; the optional email goes in the `de=` query parameter (MyMemory's API) | Email (optional) |

Not on the web: **DeepL** (CORS blocked on both hosts, W0.3), **LibreTranslate server address** and **custom Azure endpoints** (a meta-tag CSP cannot change at run time, plan decision 4). A Python check refuses any service id other than the three (`TRANSLATION_CONFIG`), so a crafted RPC cannot select DeepL.

No key is ever put in a URL. The MyMemory email is not a secret, but it is personal data and is listed in PRIVACY.md (it already is).

## 3. Where the request runs: an allow-listed XHR in the engine worker

The clients are synchronous and W2.4 rejected a TypeScript-side fetch, so the request runs in a Pyodide worker. Options:

| Option | For | Against |
|---|---|---|
| **A. Engine worker, gated XHR (recommended)** | Already decided in W1.1 (threat row I) and reserved in `engine.worker.ts`. No document needed; the text comes from the main thread. Small. | A slow service blocks the engine worker (rendering) for the request's time. A running request can't be cancelled without losing the tab's documents. |
| B. Job worker, a document-less job | Cancellable by discarding the worker (decision 5); viewing stays responsive. | New job kind with no document (`jobs.prepare` is per document); queues behind a long job such as compress; more lines. |
| C. A third Pyodide worker for translation | Never parses a PDF, so a PDF exploit cannot reach the network at all. | A second Pyodide start and heap (tens of MB, seconds) for a small feature. |

Recommended: **A**, with these limits, so the engine-worker cost stays small and the exposure stays narrow:

1. **Captured before lockdown.** `engine.worker.ts` keeps a private reference to `XMLHttpRequest` before `lockDownGlobals` runs, and never puts it back on `globalThis`.
2. **Gated wrapper.** A new `engine/translationNet.ts` exposes a constructor-like `openTranslationXhr()` to Python through `pyodide.registerJsModule('elanero_net', …)`. Its `open(method, url)` throws unless (a) the URL's origin is one of `TRANSLATION_ORIGINS` (the same three; a Vitest test checks they equal `csp.ts` `connect-src` minus `'self'`, and a Pyodide test checks they equal `WEB_ENDPOINT_ORIGINS`), (b) the scheme is `https:`, and (c) the gate is **armed**.
3. **Armed only for one call.** The worker-server arms the gate when it dispatches `translation.translate` or `translation.test` and disarms it in `finally`. No other method, and no PDF code running in another call, sees a working XHR. (A malicious PDF would need code execution in the engine *during* a translate call to use it, and could then reach only the three hosts.)
4. **`web_http.py` change (about 8 lines):** `make_xhr_opener(factory=None)`; on the web, `webapi/translate.py` passes `elanero_net.open_xhr`. The default (`from js import XMLHttpRequest`) stays for the W2.4 tests.
5. **Time bound.** The web passes `timeout` 10 s per request (desktop 20 s) and a deadline token to `translate_selection`: after 30 s in total it raises `Cancelled` between chunks, reported as `TRANSLATION_OFFLINE` with the partial text. With the size limits in §6 that is at most 5 requests for MyMemory and 1 to 3 for the others.

Cancel in the bubble (Esc, click outside, new selection) does not abort a running request: the main thread ignores the reply (the desktop says the same: "its answer is ignored"). It cannot run on, because the gate is disarmed when the call returns.

Question 1 asks the maintainer to confirm A over B.

## 4. RPC

New module `src/pdfeditor/webapi/translate.py`; DTOs in `webapi/dto.py`; types regenerated by `scripts/make_web_types.py`.

```text
translation.info  {}  ->  {services: [{id, name, privacyUrl, needsKey, detectsSource, maxChars}],
                           languages: {serviceId: [code, ...]}}
translation.translate {service, text, source: string|null, target, credentials}
                  ->  {text, detected: string|null, service}
translation.test  {service, credentials}  ->  {}
credentials = {mymemoryEmail?: string, azureKey?: string, azureRegion?: string, libreKey?: string}
```

- `info` reads the translators' own `languages()`, `max_text_chars` and `privacy_url`, so the pickers and limits come from the shared code. Language **names** are shown with `Intl.DisplayNames(locale, {type: 'language'})`, so they follow the UI language without new catalogue entries; the English name from Python is the fallback.
- `translate` builds a `TranslationConfig` from `credentials` plus the fixed LibreTranslate URL and the web opener, calls `make_translator` and `translate_selection`, and maps errors: `OfflineError`→`TRANSLATION_OFFLINE`, `QuotaError`→`_QUOTA`, `AuthError`→`_AUTH`, `ConfigError`→`_CONFIG`, `TooLongError`→`_TOO_LONG`, `SameLanguageError`→`_SAME_LANGUAGE`, anything else→`_SERVICE`. `details.partial` carries the text translated before the failure. `INTERNAL` never carries the request.
- `credentials` are never stored by Python, never logged and never echoed: the handler logs only the service id, character count and request count (as `translate_selection` already does). An `INVALID_PARAMS` error on these methods names the field, never its value (test).
- The `services.translation` in-memory cache (64 entries) stays; it lives in the engine worker and dies with it.
- The seven `TRANSLATION_*` codes leave the "declared but not raised" list in `errors.py`.
- No `core/secrets.py` store is injected: Python never persists a key on the web (§5).

## 5. Settings and their storage

| Setting | Stored where | Why |
|---|---|---|
| Translation on/off (`translationEnabled`) | `elanero.prefs` | Not personal. Off by default. |
| Service (`translationService`) | `elanero.prefs` | One of `mymemory`, `azure`, `libretranslate`. |
| Default target language (`translationTarget`, `''` = same as the app) and last From (`translationLastSource`) | `elanero.prefs` | As on the desktop. |
| Consent record (`translationConsent`) | `elanero.prefs` | §7. |
| Azure region (`translationAzureRegion`) | `elanero.prefs` | Plain text on the desktop too; not a secret. |
| MyMemory email (`translationEmail`) | `elanero.prefs` | Plain text on the desktop too; listed in PRIVACY.md. See question 4. |
| **Azure key, LibreTranslate key** | **main-thread memory only** (`translate/keys.ts`, a module-level map) | Never in `localStorage`, OPFS, the URL, logs or React state that is serialised. Lost when the tab closes or reloads. |

The prefs store already refuses field names that look like secrets (`key`, `token`, …), which is a second guard: the key fields cannot be added to `Preferences` by mistake. Keys are sent to the engine with each `translate`/`test` call (one `postMessage` inside the tab); they survive an engine restart because they live on the main thread.

W1.1 §6 also allows optional persistence, "encrypted with WebCrypto using a user passphrase" in OPFS `/secrets/` (which Clear all local data already removes). That is **not in W6.6**: it adds a passphrase dialog, PBKDF2 parameters and a forgotten-passphrase path, for a convenience. Question 3 proposes a follow-up item. Until then, Preferences says under the key fields: "Kept only while this tab is open. You enter it again after a reload."

Rule (tests enforce it): no secret appears in `localStorage`, `sessionStorage`, OPFS, the URL, `console` output or an RPC error.

## 6. Request shape and size limit

- The main thread sends the **raw** selected text (`view.selectedText()`). Python cleans it (`clean_pdf_text`) and enforces the service's `max_text_chars`: **MyMemory 2,000**, **Azure 10,000**, **LibreTranslate 10,000** characters. Above it: `TRANSLATION_TOO_LONG` (its string already tells the user to select less).
- The main thread refuses raw text over **40,000 characters** before sending (`TRANSLATION_TOO_LONG`, same message), so a select-all of a long document never crosses to the worker or blocks it. 40,000 leaves room for PDF whitespace that cleaning removes.
- Chunking (`max_request_bytes`: MyMemory 500 B, LibreTranslate 5,000 B, Azure 40,000 B) and the wire formats are the clients' own, unchanged: MyMemory `GET /get?q=…&langpair=src|tgt[&de=email]`; Azure `POST /translate?api-version=3.0&to=…[&from=…]` with a JSON body and key/region headers; LibreTranslate `POST /translate` JSON `{q, source, target, format, api_key}`.
- Only the selected text is sent: no file name, page number, document language or other text. The document's `/Lang`, if any, only preselects **From** on the main thread (as on the desktop), and From starts at **Detect language** otherwise.

## 7. Consent flow and record

1. The user selects text and chooses **Translate** (selection mini toolbar, §8).
2. If translation is off, or `translationConsent` does not match the current service and notice version, the **consent notice** opens (react-aria `Dialog` on the Overlay host) **before anything is sent**:
   - Title: "Translate the selected text with {service}?"
   - Body: "Only the text you selected is sent to {recipient}. It sees the text and your IP address. Nothing is sent until you choose Translate. You can turn this off in Preferences ▸ Translation." Recipient: "MyMemory (Translated.net)", "Microsoft Azure AI Translator", or "the LibreTranslate public server at libretranslate.com (its operator's privacy policy applies)".
   - Buttons: **Translate** (default), **Cancel**, and a **Privacy policy** link that opens the service's policy in a new tab (through the existing link-confirm path, `rel="noopener noreferrer"`) and leaves the notice open.
3. **Translate** writes `translationEnabled: true` and `translationConsent: {service, version: 1, at: <ISO date>}`, then sends. **Cancel** writes nothing and sends nothing.
4. Consent is per **service** (on the web the endpoint is fixed, so the service id is the desktop's `cache_id` in effect; the Azure region does not change the recipient). Changing the service, or a later notice bumping `version`, asks again. Turning translation off in Preferences clears `translationConsent`.
5. A key-needing service with no key in memory opens Preferences ▸ Translation instead of the notice (the desktop's `ConfigError` path), and sends nothing.
6. **Test connection** in Preferences sends a short fixed text ("Hello"), not document text. It requires the same consent and shows the same notice if missing.

The record is local only: it proves to the app, not to a server, that the user agreed. It is removed by Clear all local data (it lives under `elanero.`).

## 8. The bubble

- **Entry points:** a small **selection toolbar** that appears next to a non-empty text selection with **Copy** and **Translate** (the desktop's "mini toolbar"; the web has none yet, so W6.6 adds it with these two buttons), the command palette entry "Translate selection" (registry id `translate-selection`, enabled only with a selection), and the keyboard: the palette is the keyboard path; no new shortcut (question 6).
- **Placement:** anchored to the selection's last line rectangle on the page (`selection.pageRects`), using the same placement helper as the comment toolbar; it flips above when there is no room below and becomes a bottom sheet under the narrow layout.
- **Contents:** From picker (Detect language + the service's languages), a swap button (disabled when From is Detect), To picker (default `translationTarget`, else the UI language, else English), the translation in a read-only, selectable region with `aria-live="polite"`, the service name ("Translated by MyMemory"), and **Copy** and **Add as note**. While waiting: a spinner and "Translating…". Changing From or To runs the translation again (the cache answers repeats).
- **Copy** writes the translation with `navigator.clipboard.writeText` (the existing `text/copy.ts` helper) and shows the "Copied" toast.
- **Add as note** runs a new action `annotations.highlight_text` (§9) with the selection's per-page rectangles and the translation as the note, one undo step "Add Note to Text", author = `authorName`. It is disabled when the document is read-only or busy, and when the selection has changed since the bubble opened (the desktop asks the user to select again).
- **Closing:** Esc, a click outside, a new selection, a scroll or zoom, or a tab switch closes the bubble; a reply that arrives later is dropped (request id check).
- **Accessibility:** a non-modal `role="dialog"` with a label, focus moves into it on open and back to the page on close, Tab cycles inside it; all strings via `t()`.

## 9. Add as note: one small action

`annotations.create` takes one rectangle; a highlight of a multi-line or multi-page selection needs one quad per line and one annotation per page. New action in `actions/comment_tools.py`:

```python
@dataclass(frozen=True, slots=True)
class HighlightText:
    pages: tuple[PageRects, ...]   # (page, rects) in visible-space points
    note: str = ""
    author: str = ""
```

It builds one `build_markup(HIGHLIGHT, …)` per page with `quads = (Quad.from_rect(r) for r in rects)` and the union as `rect`, puts `note` on the first only (desktop `apply_markup`), clips to the page, caps rectangles at 2,000 per call (`Refused`), and executes all `AddAnnotationCommand`s as one undo step. Desktop code is unchanged; W7's text-markup tools can reuse it.

- **Vitest `translate/*.test.tsx`:** no RPC before consent; Cancel sends nothing and records nothing; Translate records `{service, version, at}`; a service change asks again; turning off clears the record; key-needing service without a key opens Preferences; offline (`navigator.onLine` false) sends nothing; each error code shows its string; partial text shown with the note; From/To change re-runs; Copy writes the clipboard; Add as note calls `annotations.highlight_text` with the rects and is disabled after the selection changes; a late reply after close is dropped; over 40,000 characters refused before RPC.
- **Vitest secrets:** after entering keys and translating, `localStorage`, `sessionStorage` and a fake OPFS contain neither key; `console` spies saw neither; the prefs store refuses `translationKey`.
- **Vitest Preferences:** no DeepL row, no server-address row; Forget key clears memory.
- **e2e (W8.1, optional):** a Playwright spec with `page.route` fulfilling the three hosts, so the browser path is covered without the network. Not a required check.

## 17. Risks

| Risk | Mitigation |
|---|---|
| Re-opening a network path in the worker that parses untrusted PDFs | Captured XHR never on `globalThis`; origin allow-list identical to the CSP; armed only during a translate/test call. The CSP is the outer wall either way. W8.6 reviews it. |
| A slow service freezes rendering | 10 s per request, 30 s total, at most ~5 requests; main-thread cap of 40,000 characters. Option B if this proves bad (question 1). |
| MyMemory stores submitted text in a public translation memory | Stated in the notice through its privacy link; MyMemory is the default only because it needs no key. Question 5. |
| Keys lost on reload annoy users | Stated in Preferences; encrypted persistence as a follow-up (question 3). |
| CORS policies change (W0.3 was a snapshot) | Shows as offline; the `web-cors` workflow can re-probe; the guide says the service may be unreachable. |
| Public LibreTranslate needs a paid key | Stated in Preferences and the guide. |
| The privacy policy says "planned, not in this build" | Owner decision (question 2) gates S2/S3. |
| Synchronous XHR deprecation | Allowed in workers in all three engines today (W2.4 tested it); revisit if a browser warns. |
