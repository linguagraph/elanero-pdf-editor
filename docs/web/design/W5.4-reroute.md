# W5.4: Copy, Select All and Mark Text on the selection model

Stage: W5 · Role: design Opus 5.5 · Branch: `phase-w-w5.4-reroute-model` · Inputs: [W1.4](W1.4.md) §10, [plan](../plan.md) W5.4 and W4.12, PRs #374 (Mark Text), #402 (TS model), #407 (Copy and Select All), #486 (SelectionMarks), #514 (pointer drag), #515 (Playwright specs). Line numbers are for `main` at 63420ed.

W1.4 §10 decided that the web's selection is the desktop's model (`TextSelection` over `PageTextIndex`), not the browser's selection over the DOM text layer. #486 and #514 made the model draw and build the selection. Three commands still read the browser's selection, fully or as a fallback: Copy, Select All and Mark Text. This note routes all three through the model. The browser's selection is still read, but only where the model is not in charge (§5).

## 1. Where things stand

The model is in charge of a page while the view's `selecting` is true (`DocumentView.tsx:487`: the Select tool, with no armed comment, redaction-mark or crop tool). The page's text layer then has the class `page-text-layer--model`, and its spans have `user-select: none` (`textLayer.css:36`). As a result, **the browser can't make a selection on those spans**. A drag only builds the model selection: `useTextSelection.startPress` calls `preventDefault`.

| Command | Handler today | What it reads | Effect under Select |
|---|---|---|---|
| Copy (Ctrl+C, Home ▸ Tools) | `App.tsx:292` `copy` → `copySelectedText` (`text/copy.ts:60`) | `modelText()` (handle `selectedText`, `DocumentView.tsx:859`), and when that is null, the browser's selection through `selectedText` → `domSelectionAreas` (`copy.ts:29`) | Works for a drag. When a covered page has no index, it falls back to the browser's selection, which is empty, so the user is told "Select some text" even though text is drawn as selected |
| Select All (Ctrl+A, Home ▸ Tools) | `App.tsx:568` `select-all` → handle `selectPageText` (`DocumentView.tsx:847`) | The top page's index → `TextSelection.ofPage`. Without an index, it falls back to `selectPageText` (DOM range, `copy.ts:83`) | Works when the index is ready. The fallback selects an empty layer: when the index is missing, no spans are drawn yet (lines and index arrive in the same cache entry), so nothing is selected |
| Mark Text (Protect ▸ Redact) | `App.tsx:577` `mark-text` → `markSelectedText` (`redaction/markText.ts:24`) | **Only** `domSelectionAreas(window.getSelection(), cachedLines)` | **Broken since #514**: a drag makes no browser selection, so Mark Text always says "Select some text on a page first" |

The handle under Hand has two more defects:

- Under Hand, Select All sets a model selection that is neither drawn nor copied, because `selectedText` returns null when `!selecting`.
- The effect at `DocumentView.tsx:513` clears the model only on the change *to* not-selecting. A Select All made under Hand therefore shows up when the user goes back to Select.

## 3. Source of the text and the areas

`ModelRead<T>`, in `selection.ts`:

```ts
export type ModelRead<T> =
  | { readonly state: 'off' }                    // the model is not in charge: read the browser's selection
  | { readonly state: 'loading'; readonly pages: readonly number[] } // covered pages without an index yet
  | { readonly state: 'ready'; readonly value: T }; // '' or [] when nothing is selected
```

- **Text.** The source is `TextSelection.text(pages)` (`textSelection.ts:61`), through `readModelText`. It builds a `PageIndexes` from `textLayers.readyIndex(page, revisionOf(page))` for every page from `start.page` to `end.page`. If any of those pages has no index, the result is `loading`, with the missing pages listed. There is no partial text (decision D4: never copy part of a selection).
- **Areas.** The source is new code, `modelSelectionAreas(selection, pages)`. For each `pageSpans` entry `{page, start, end}`, it sets:
  - `rects` to `index.rects(start, end)`, which gives one rect per line, with separators and boxless chars skipped, the same rule as `selectionAreas`;
  - `quads` to one quad per rect (`ul/ur/ll/lr` from x0/y0/x1/y1, as `selectionAreas` builds them);
  - `rect` to the union of the rects;
  - `text` to `index.extract(start, end)`.

  A page with no rects gives no area. The result is one `PageArea` per page, as today, so `controller.markAreas` and `pageAreaJson` don't change, and one press is still one undo step.
- The handle answers `off` when `selectingNow.current` is false. It answers `ready` with `''` or `[]` when the model selection is null or empty.

## 4. Line-break rules Copy must keep

These rules are pinned by `copy.test.ts`, `DocumentView.copy.test.tsx` and `e2e/features/text.spec.ts`. The model already follows all of them, so the reroute keeps them by construction:

1. Lines within a page are joined by exactly one `LINE_SEP` (`'\n'`). This is the engine's separator char in the index text, so `extract` returns it as part of the span.
2. Pages are joined by one `LINE_SEP` (`TextSelection.text`, the desktop's `TextSelection.text`). A page whose span is empty adds nothing, not an empty line (`pageSpans` drops `to <= from`, as `webapi.text.extract` does).
3. There is no trailing line break. A selection that starts or ends on a separator carries that `'\n'`, as on the desktop.
4. Code points, not UTF-16 units: offsets are code points (`PageTextIndex.chars`), so a surrogate pair is never split.
5. Known differences from the DOM path, both closer to the desktop:
   - The DOM path dropped lines that are whitespace-only or have no boxes (`decodeTextLayer` filters them). The model keeps their text, as the desktop does.
   - `text.spec.ts` builds its expected text from the visible spans (`lineTexts` skips blank spans). It still passes on `text_multipage.pdf`, which has no blank lines.

`MAX_COPY_CHARS` (50 MB, refused whole) is unchanged.

## 5. When the browser's selection is still read

Keep `domSelectionAreas`, `selectedText(selection, lookup)` and `selectPageText(selection, layer)`, and read them **only when the model answers `off`**. That happens when `selecting` is false: the Hand tool (a page not in the model's charge keeps `user-select: text`), or no document view.

- **Why under Hand:** on those layers the browser's selection is the only one. A user can make one with the keyboard, with a screen reader's selection commands, or with a touch long-press, because Hand leaves one-finger touch to the browser. It is the path `DocumentView.copy.test.tsx` already pins ("then the native selection once Hand is chosen").
- **Why not for "no text layer yet":** under Select, a page whose index hasn't arrived has no spans either. Lines and index come from the same `TextLayerCache` entry, and the layer is `--model`. The browser's selection over such a page is always empty, so the fallback can't help. Today it turns "still loading" into the wrong message. The model handles the case itself:
  - **Copy:** for `loading`, request the missing indexes (`textLayers.index(page, revisionOf(page))`), and show `text.stillLoading`. Copy can't wait for them: the clipboard write must stay synchronous inside the keypress, because Firefox and Safari require it (`copy.ts:58`). The next press succeeds.
  - **Mark Text:** for `loading`, await the same requests (Mark Text has no user-activation limit), then read the selection again. If a page still fails, show `text.stillLoading` and mark nothing.
  - **Select All:** when the top page's index is missing, request it and set `TextSelection.ofPage` when it arrives. Only do this if `selecting` is still true and the top page is the same; otherwise do nothing. No DOM range is made.

## 6. Select All semantics

Select All keeps **the page at the top of the view**, as the guide states today. It doesn't select the whole document, as the desktop's `DocumentView.select_all` does. Why:

- A whole-document selection would make Copy and Mark Text need every page's index, and those indexes aren't loaded: the cache holds 300 pages, and pages arrive only when shown or asked for.
- Copy would then have to use the chunked `text.extract` (W1.4 §10, "larger selections, including Select All on a long document"). The clipboard write would then be asynchronous (a `ClipboardItem` with a promise, or a second press).

That is the "large copies as chunked worker calls" part of W5.4, a separate slice. Select All of one page needs only the top page's index, which is loaded or about to be because the page is in view. It never needs pages that aren't loaded. The selection still uses the cross-page model, so the later slice can widen it to `{0,0}`–`{last,len}` without touching Copy's line rules.

## 13. Risks

- **Stale offsets after a revision change.** Mark Text clears the selection, because the marks bump the page revision. But an Undo or Redo on a covered page while Select is on leaves the model with offsets from the old index. Copy then answers `loading` until the new layer arrives, and may then select different chars. Mitigation (recommended, about 8 lines): clear the model selection when any covered page's revision changes. See question 3.
- **Asynchronous Mark Text.** Waiting for indexes lets the user act in between, for example by changing tools. Re-read the model after the wait. If it is now `off` or `ready []`, mark nothing; never mark a selection the user has dropped.
- **Requests from Copy.** The `loading` branch asks for pages that might not be mounted. Bound it to the pages in the selection, at most `MAX_TEXT_LAYERS` (300). The large-copy slice owns larger selections. Until it lands, a selection over more than 300 pages can't be copied. This is very unlikely with a drag.
- **Touch under Select.** `--model` sets `user-select: none`, and `startPress` ignores touch, so a touch user can't select text under Select at all, only under Hand. This predates the reroute (#514), and the note doesn't fix it. See question 4.
- **Whitespace-only lines in marks.** `index.rects` keeps a box for a boxed whitespace-only line, which the DOM path dropped. The mark gets one more thin quad. This is harmless for redaction (it covers less than a page mark), but it is a visible change in the panel's area.
- **Fallback hides bugs.** If `selecting` and the layer's `--model` class ever disagree (today the layer uses `tool === 'select'` while the handle uses `selecting`), a page could be in neither path. Make `PageTextLayer`'s `selection` prop use `selecting` too (1 line), so the two always agree.

## Questions for the maintainer

1. **Select All scope: the top page (as now) or the whole document (the desktop)?** Recommended: the top page in this slice. Widen it to the whole document in the large-copy slice, where `text.extract` and an asynchronous clipboard write make it possible.
2. **Copy when a covered page's text hasn't arrived: refuse and ask to retry, or wait?** Recommended: refuse with `text.stillLoading` and request the pages. Waiting breaks the synchronous clipboard write on Firefox and Safari. Mark Text may wait, because it has no such limit.
3. **Clear the model selection when a covered page's revision changes (Undo, Redo, an edit)?** Recommended: yes. It is cheap, it removes the stale-offset risk, and a user expects an edited page to drop its selection.
4. **Touch selection under Select** (no long-press selection today): fix it here or separately? Recommended: separately, as a W8.5 (coarse pointer) follow-up. It needs a long-press gesture in `useTextSelection`, which is out of this reroute's scope.
5. **Enable the Mark Text leak test in `redaction.spec.ts` in this PR?** Recommended: yes, with a pointer drag. It is the only end-to-end check that Mark Text works on the model, and the reason it was blocked is gone.
