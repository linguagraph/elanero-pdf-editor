## 2. What the audit reports

Each category is the **stored** size of the objects of one kind: the object's text plus its raw
(still compressed) stream, summed. The categories, in `SPACE_CATEGORY_KEYS` order: images, fonts,
page content, comments and forms, structure (tags), bookmarks and links, embedded files, metadata
and thumbnails, other objects, and file overhead (the file's length minus the sum, at least 0). All
ten are always present, zeros included.

Measured on the generated fixtures (desktop, `screen` and `lossless`):

| File | before | audit_before.total | after | audit_after.total |
|---|---|---|---|---|
| report.pdf | 11 534 | 11 534 | 7 038 | 7 434 |
| heavy.pdf | 7 762 723 | 7 762 723 | 22 942 | 26 707 |
| perf_mixed_200.pdf | 4 410 610 | 4 410 610 | 568 274 | 610 672 |

`audit_before.total` equals `before` (both are a default save). `audit_after.total` is **not**
`after`: the reduced file packs objects into object streams, and the audit counts each object at its
own text length and measures the total by a default re-save. The difference was 5 to 16 % on these
files, always upward. So the table must not put an audit total next to the headline's exact sizes
(§4). The audit took 60 ms for 200 pages on the desktop; under Pyodide expect a few times that.

## 3. When it runs, and where

Both measurements are taken **inside the one `reduce_size` job**, in the job worker: `audit_before`
on the job's document at step 0, the reduce at steps 1 to 4, `audit_after` on the reopened reduced
bytes at step 4 (progress 0 to 5, already in S1). The dialog sends `audit: true` on every run. Nothing
runs on the main thread and no second job is needed.

Not on dialog open, as a separate `audit` job, because:

- One job at a time: the bar refuses a second one with `BUSY` (`fileJob.ts:180-184`). An audit that
  is still running when the user presses Compress would make Compress fail, and an audit started while
  another job runs (a split, an export) would fail on open.
- Each job starts a job worker and copies the document to it (W3.9 memory warning), only to show a
  table the user did not ask for.
- The `audit` job returns kind `report`, which the file job flow does not read; supporting it is
  part of the Space Audit command (Q2), not this slice.

So "before" and "after" both appear once the run has finished, from the same job, measured on the
same document state. The extra cost is one open of the reduced bytes in the job worker; the reduce's
work copy is already closed by then, so the peak memory is about the same as without the audit.

A failed audit must not cost the user the reduced copy. Today an exception in `space_audit` fails the
whole job. Recommended (Q3): in `_run_reduce`, catch `EngineError` around each audit, log it, and send
`None`; the dialog then shows the result without the table.

## 4. Layout and accessibility

The result section (`CompressDialog.tsx:239-277`) becomes:

1. The headline sentence, unchanged, in its `role="status"` paragraph: exact file sizes and percent,
   or the "not smaller" message.
2. The download link or the Keep button, unchanged.
3. **The audit table**, when both audits are present.

The table is a real `<table>`, not a definition list: each part has two values and a change, which is
two-dimensional data, and a `<dl>` would make a screen reader read "Images, 1.2 MB, 300 KB, 900 KB
less" with no column names. With a table, a screen reader announces the column header as the user
moves across a row.

```
Space by part (Balanced (ebook))
Part                 Before     After     Change
Images               6.9 MB    210 KB    6.7 MB less
Fonts                412 KB     98 KB    314 KB less
Page content         120 KB    120 KB    No change
File overhead          2 KB      1 KB    1 KB less
Part sizes are measured object by object, so they need not add up to the file sizes above.
```

- `<caption>` is the visible heading and names the settings that ran: `compress.audit.caption`
  with the preset's label (`Custom` for custom). It is the table's accessible name.
- `<th scope="col">` for Part, Before, After, Change; `<th scope="row">` for the part's name.
- The change is words ("{size} less", "{size} more", "No change"), not a sign or a colour: a screen
  reader may skip "−", and colour alone fails WCAG 1.4.1. No colour is added.
- Numbers are right-aligned with `font-variant-numeric: tabular-nums`.
- Rows: those where before or after is non-zero, summed by key (two engine labels can both map to
  `other`), sorted by the before size, largest first, ties in `SPACE_CATEGORY_KEYS` order, with file
  overhead always last. No total row: the true totals are in the headline, and an audit total would
  disagree with them (§2). The note under the table (`compress.audit.note`, a `<p>` tied with
  `aria-describedby` on the table) says why the parts need not add up.
- Width: four short columns fit 320 px with the 16 px gutter at the default text size. The table
  sits in a wrapper with `overflow-x: auto` for large text; the wrapper is `role="group"`,
  `aria-labelledby` the caption and `tabIndex={0}`, so it can be scrolled by keyboard (axe
  `scrollable-region-focusable`).
- Not a live region: the headline's `role="status"` already announces the result; reading a whole
  table aloud on finish would be noise. Focus does not move.
- Forced colours: borders use `--color-border`, as the rest of the dialog does; no information is in
  background colour, so nothing is lost when the browser replaces colours (check it with
  `e2e/forced-colours.spec.ts`).

## 5. The "not smaller" case

Unchanged: the message stays, no download is offered (`offered` is undefined, no blob URL is made),
and **Keep the original** closes the dialog. The table **is** shown: it explains why (for example,
images already at a lower resolution, so the change is "No change" on Images). The caption's preset
name makes clear which settings produced the numbers. The message key `compress.notSmaller` starts with
"This preset does not make the file smaller"; with Custom that is wrong, so it becomes "These settings
do not make the file smaller: …" (one string, same placeholders).

## 6. Presets, custom options and stale results

- The audit reflects the settings that **ran**, not the current fields. The `Outcome` keeps the
  settings' label (`PRESET_LABELS[preset]` or `compress.preset.custom`) for the caption.
- Changing the preset or any field after a result **clears the result** (`setOutcome(null)`), as the
  desktop clears its estimate on any change (`ui/dialogs/optimize.py`, `show_estimate(None)`). This
  also revokes the download link (the `links` memo frees it), so a download can never be of settings
  other than those shown. Today the result stays after a change; that is the stale-result bug this
  fixes.
- A custom run equal to a preset gives the same bytes as the preset (S1), so the audit is the same too.
  The caption still says Custom, which is accurate.

## 7. Sizes and i18n

`formatSize` (`CompressDialog.tsx:65-72`) formats with `toFixed(1)`, which ignores the locale ("1.5"
in German too). Keep its `compress.size.*` keys (they let a translator write "Ko"), but format the
number with a new `formatDecimal(value, digits)` in `i18n/format.ts` (an `Intl.NumberFormat` with
`minimumFractionDigits` and `maximumFractionDigits` equal, cached per locale like the others), so
English output is unchanged and the existing `formatSize` test still passes. The table and the
headline use the same `formatSize`, so the two never disagree in format. `formatMegabytes` is not
used: it is MB only and drops the trailing ".0".

New keys in `en.ts` (English only exists today):

| Key | English |
|---|---|
| `compress.audit.caption` | `Space by part ({settings})` |
| `compress.audit.part` / `.before` / `.after` / `.change` | `Part` / `Before` / `After` / `Change` |
| `compress.audit.less` | `{size} less` |
| `compress.audit.more` | `{size} more` |
| `compress.audit.same` | `No change` |
| `compress.audit.note` | `Part sizes are measured object by object, so they need not add up to the file sizes above.` |
| `space.category.images` … `space.category.file_overhead` (10) | the desktop's labels: Images, Fonts, Page content, Comments and forms, Structure (tags), Bookmarks and links, Embedded files, Metadata and thumbnails, Other objects, File overhead |

The category keys are under `space.`, not `compress.`, so the Space Audit command (Q2) reuses them.
They are mapped by a `Readonly<Record<SpaceCategoryKey, MessageId>>`, so a new key in
`SPACE_CATEGORY_KEYS` fails the typecheck until it has a string. The engine's English `name` stays
unread. Changed: `compress.notSmaller` (§5).

## 10. Test plan

- **Vitest, `compressJob.test.ts`**: `auditRows` drops rows zero in both, sums two `other` entries,
  sorts by before size with file overhead last, computes less, more and same; an absent audit gives
  no rows.
- **Vitest, `CompressDialog.test.tsx`** (fake job worker, as now): the job is sent `audit: true`; after
  a smaller result the table has a caption naming the preset, four column headers, row headers by
  t() label, and "… less" text; in the "not smaller" case the table shows and no `<a download>`
  exists; Custom shows "Custom" in the caption; changing a preset or field after a result removes
  the result and revokes its link (spy on `URL.revokeObjectURL`); a reply with null audits shows the
  result without a table; `formatSize` keeps its English output.
- **Vitest, `format.test` or `i18n.test.ts`**: `formatDecimal(1.5, 1)` is "1.5" in `en` and "1,5" in
  `de`.
- **Vitest, `components.a11y.test.tsx`**: an axe run of the dialog in the result state with the
  table (the current test covers only the empty form).
- **Usage test** (`i18n/usage.test.ts`): every new key is used and every `SpaceCategoryKey` has one.
- **pytest, `tests/unit/test_webapi_jobs.py`** (host and Pyodide): a document whose audit raises
  still returns the reduced file with `audit_before` and `audit_after` null (monkeypatch
  `space_audit`), and the warning is logged. The existing audit tests stay.
- **Playwright, `e2e/features/compress.spec.ts`** (new, three browsers, the W8.1 feature run): open
  `images.pdf`, Reduce File Size, Smallest, Compress; the table appears with Images showing "less";
  the downloaded `reduced.pdf` is smaller than the original; then Lossless on an already reduced file
  shows the "not smaller" message, the table and no download. This is the "end-to-end run in the app"
  the PLAN note says is not yet checked; the axe spec (`axe.spec.ts`) gets the result state.
- **Manual**: NVDA with Firefox and VoiceOver with Safari read the column header when moving across
  a row; 320 px width with 200 % text scrolls the table inside its wrapper.

## 11. Risks

- **Parts that do not add up.** The after-audit's parts exceed the reduced file by up to about 16 %
  (§2). Mitigated by no total row and the note. Fixing the measurement (counting object-stream
  members at their share of the packed stream) is a desktop and web service change, out of scope (Q1).
- **A slower result on large files.** The after-audit reopens the reduced bytes; for a 200-page file
  this was 60 ms on the desktop. Under Pyodide, budget a few hundred ms more per run, inside the
  job, with the bar showing step 4 of 5. Acceptable; no toggle.
- **A shape error now fails the compress.** `readAudit` throws on a bad audit, failing a run that
  produced a good file. The shape is generated and checked on both sides, so the risk is a version
  skew, which the protocol version check already refuses.
- **Wrong caption after a change.** Avoided by clearing the result on any change (§6).
- **Size of the dialog.** The dialog grows by up to eleven rows; on a phone it scrolls inside the
  Overlay, which already scrolls. The headline and download stay above the table, so the action is
  never below the fold of the result.

## Questions for the maintainer

1. **Should the audit's object-stream over-count be fixed now?** Recommended: no. Ship the table
   without a total row and with the note; open an issue for `engine/mupdf/optimize.space_usage` to
   measure packed objects, which also fixes the desktop's Space Usage dialog.
2. **Should the `space-usage` command (Space Audit) be wired in this slice?** Recommended: no. It
   needs a report-kind job reader in `fileJob.ts` and its own dialog; make it a separate W6.4 follow-up
   (or a W7 item) that reuses `SpaceAuditTable` with one column and the `space.category.*` keys.
   Until then the guide points to the compress result.
3. **Should a failed audit fall back to no table instead of failing the job?** Recommended: yes
   (§3); about 15 lines in `webapi/jobs.py` plus one test. The audit is a display aid; the reduced
   file is what the user asked for.
4. **Can W6.4 be ticked with this PR?** Recommended: tick it only if the new Playwright spec passes
   on all three browsers in the PR's `web-e2e` run (on demand); otherwise update the partial note to
   "pending: the end-to-end run" and tick in the follow-up PLAN PR, as with the other parallel ticks.
5. **Should the audit be optional (a checkbox)?** Recommended: no. Always on: the cost is small and
   inside the job, and the desktop's Space Usage gives the same information unasked for.
