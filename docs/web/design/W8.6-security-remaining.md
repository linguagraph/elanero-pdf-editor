### 3.4 S8: guard the XMP parser (F8)

- In `core/xmp.py._parse`: refuse a packet longer than a cap (8 MiB, the XFDF figure) or holding
  `<!DOCTYPE` or `<!ENTITY` before `ET.fromstring`, with the same reasoning as
  `services/xfdf.py:54-61` (expat parses `str` input as UTF-8, so the literal check is sound).
  `core` cannot import `services`, so the check is a small local helper, not a shared import.
- Behaviour on refusal (question 3): today a `ParseError` silently replaces the packet with a
  fresh one, which drops PDF/A identification. Recommended: on a refused or unparseable packet,
  `sync_xmp` returns the original packet unchanged and logs a warning, so a metadata edit never
  destroys XMP it could not read. This is also a desktop behaviour change and the PR says so.
- Production: **about 25** (`core/xmp.py`, mypy strict). Tests: about 80 (billion-laughs,
  external entity, oversized and UTF-16 DOCTYPE packets through `sync_xmp`; a round trip that
  edits the title of a file with a hostile packet, saves, reopens in pikepdf and checks the packet
  is unchanged; pypdfium2 renders it).

## 5. Tests and what a failure looks like

- CSP: `csp.test.ts` names the missing or extra directive or origin.
- Drift: Vitest prints the client and engine values side by side.
- Depth: pytest gets a `RecursionError`-path message or a success instead of "nested too deeply".
- XMP: a hostile packet reaches `ET.fromstring` (a mock counts calls), or the saved packet differs
  from the original.
- Frame and JavaScript: Playwright sees `#root` content in the frame, a dialog, a console message
  or a new page.
- Signing and service worker: the zip holds a signing path, or a cache changed after an unlisted GET.

## 6. Risks

- **F7 on three browsers.** A `trusted-types` allow-list can break worker start or the service
  worker in one browser only. Mitigation: ship it only after the three-browser features run; else
  defer with a note.
- **XMP behaviour change on the desktop.** Keeping an unreadable packet instead of replacing it
  changes what desktop metadata edits write. Mitigation: a round-trip test on both paths; the PR
  says so.
- **Browser specs need staged assets.** S6b's specs run only in `web-e2e` (nightly or manual), so
  a PR can merge with them unrun. Mitigation: run them locally on three browsers and say so in the
  PR, as #439 did.
- **`--ignore-scripts` breaks a build tool** silently in the deploy job. Mitigation: try on a
  branch with a manual `web-deploy` dry run before merging, or defer to W9.1.
- **The report goes stale again.** It describes main at one commit. Mitigation: the checklist in
  S1 goes into the review of every web PR, and the guards in S2, S2b, S4b and S9 run on every PR.
