### 2.1 `annotations.create`: the argument change

`CreateAnnotation` (`comment_tools.py:85-95`) gains one field, so the wire stays one shape and old calls still convert:

```python
points: tuple[Point, ...] = ()  # ink stroke, line ends, polygon vertices, or the callout's tip
```

`CommentTool` gains `textbox`, `callout`, `pen`, `line`, `arrow`, `oval`, `polygon`, `polyline`, with the desktop's undo labels ("Add Text Box", "Add Callout", "Add Drawing", "Add Line", "Add Arrow", "Add Oval", "Add Polygon", "Add Polyline"; `annotate.py:183-191`, `:265`, `:275`, `:326`, `:377`, `:509`). New builders, all in `comment_tools.py`: `build_text_box`, `build_callout`, `build_ink`, `build_line`, `build_poly`. Per tool:

- `rect` is used by note (top-left), rectangle, oval, text box and callout (the box). A zero-area box for a text box or callout means "a click": the default box (180×40 at the point; for a callout `_default_box(tip, at)`).
- `points` is used by pen, line, arrow, polygon, polyline and callout (exactly one point, the tip). The bounding `rect` of a point tool is computed in Python from the points (`Rect.from_points`), so the web sends `rect` as the points' bounds only for symmetry; Python ignores it for those tools.
- Text box and callout with empty or whitespace-only `text` add nothing (`executed: False`), as the desktop's `if not text: return`.

**Input limits (web input is untrusted; new, shared with the desktop):** `Refused` for more than 10 000 points (a long pen stroke at 60 Hz is about 1 000), a wrong point count (line and arrow: 2; callout: 1; polygon: at least 3 after de-duplication, polyline at least 2), text over 64 KiB; every point is clamped to the page rect (the web clamps too, `coordinates.ts:59-71`). `from_json` already refuses NaN and infinity.

### 2.2 `annotations.mark_text`: the markup tools

A new action in `comment_tools.py`, because one gesture can cover several pages and must be one undo step (the desktop's `apply_markup` commits a list, `annotate.py:158-173`):

```python
@dataclass(frozen=True, slots=True)
class MarkupArea:
    page: int
    quads: tuple[Quad, ...]   # one per line, visible space (the web's PageArea.quads)
    text: str = ""

@dataclass(frozen=True, slots=True)
class MarkText:
    kind: CommentTool          # highlight | underline | strikeout | squiggly
    areas: tuple[MarkupArea, ...]
    author: str = ""
```

One `AddAnnotationCommand` per area with quads, its `rect` the union of the quads, the first area's `contents` the selected text and the rest empty, run through `execute_all` with the desktop's label. Refused: a kind that is not a markup, more than 300 areas (`MAX_TEXT_LAYERS = 300`, the page span the web can read, `text/textLayerCache.ts:16`), more than 5 000 quads in total, a page out of range. An area with no quads is skipped. The web gets the areas exactly as Mark Text for redaction does (`redaction/markText.ts:37-74`: the model selection, `domSelectionAreas` as the fallback); this is the same `PageArea` (`text/textLayer.ts:47-52`).

## 3. Selection, move and resize

### 3.1 Data: `comments.page`

The panel's `comments.list` is the wrong source for hit testing: it is whole-document, capped (`MAX_COMMENT_ENTRIES`), read only while the panel is open (`controller.ts:115-120`), carries the raw `/Rect` (for a line this includes the line-ending margin) and no hidden flag. W1.5 §2 already planned a per-page read. New RPC **`comments.page`** (`webapi/actions.py`), params `{handle, page}`, result:

```
{ revision, threads: [ { comment: CommentDto + {bounds, hidden, movable, resizable}, replies: [CommentDto] } ] }
```

- `bounds` is `annotation_bounds` (`ui/view/document_view.py:1274-1285`), which is pure geometry; it moves to `actions/edit_geometry.py` (the desktop imports it from there; `select._bounds` follows).
- `hidden` is `flags & FLAG_HIDDEN` (`model/annotations.py:190`); `movable` is "not locked and not a markup" and `resizable` is "not locked and not a note or attachment" (`select.py:34-40`, `:105`), computed in Python so the two apps share the rule.
- Order: the page's annotation order, so "topmost" is the last one, as `annotation_at` (`document_view.py:1117`).
- No cap per page beyond the engine's own list; a page with thousands of comments is still a small reply.

The TS side gets a `CommentPageCache`, a copy of the shape of `edit/objectCache.ts` (keyed by page and revision, LRU, failed reads forgotten). `generated.ts` is regenerated (`scripts/make_web_types.py`).

### 3.2 Hit testing

`commentAt(threads, point, tol)`: the last root whose `bounds` inflated by 3 screen pixels (in points: `3 / (zoom × CSS_PX_PER_POINT)`) contains the point, skipping `hidden` ones (`document_view.py:1110-1122`). Ported with vectors: `scripts/make_edit_vectors.py` gains a `comment_at` and an `annotation_bounds` section, checked by `hitTest.test.ts`. Handles, resize and the fit matrix reuse `handleAt`, `resizeBox` and `fitMatrix` (`edit/hitTest.ts:52-125`) unchanged: they are already the desktop's `HANDLE_PX = 6`, `MIN_SIZE = 4` and `_fit` (`select.py:41`, `:67-73`).

### 3.3 Gestures (Select tool)

A `CommentSelectLayer` per visible page while the view tool is Select and no comment or mark tool is on. It listens in the capture phase so a press on a comment wins over the text layer (the desktop checks comments first, `select.py:198`); a press elsewhere falls through to text selection unchanged.

- **Click** a comment: select it (Ctrl or Cmd toggles, `select.py:128-131`). Click empty page: clear. Selected comments get an outline; with exactly one resizable comment selected, eight handles.
- **Drag** a selected movable comment: preview the boxes translated; on release, a move under 0.5 pt (`select.py:174`) is a click, else `annotations.transform` with the refs, the translation matrix and `resize: false` ("Move Comment"). Only comments on the pressed page move (`select.py:134-138`).
- **Drag a handle:** `resizeBox` then `fitMatrix`, `resize: true` ("Resize Comment"); a callout keeps its tip (`reshaped`, `actions/comments.py:113-119`).
- **Click a note without dragging** opens its popup (section 4), as `select.py:175-176`. Double-click any other comment opens the Comments panel at its thread (the desktop opens a text prompt, `main_window.py:1429-1445`; the web's in-place edit lives in the panel, W7.1b).
- **Delete or Backspace** deletes the selection with `annotations.delete` (locked ones stay, `actions/comments.py:383-385`). The key handler is the Edit tool's (`DocumentView.tsx:677-695`), widened to the comment selection.
- **Escape** clears the selection (`document_view.py:785-791`).
- The Undo toast follows each step (`feedback/undoToast.offerUndo`, as `placement.ts:62-68`).

### 3.4 The stale-object rule

Comments are addressed by `AnnotRef(page, name)`, not by a per-revision key, so a ref survives unrelated changes and a full save (`current_name`). The rules:

1. **The page changed under a drag.** If the page's revision moves while a drag is in progress (the scheduler's `subscribeRevisions`), the drag is dropped with no call, and the selection is pruned to the refs the new `comments.page` still holds. The matrix is relative, so without this rule an undo during a drag would move the comment from its restored place by the old offset.
2. **The comment is gone.** `annotations.transform`, `annotations.delete` and `annotations.set_text` answer `STALE_OBJECT`; the web refetches the page, clears the selection and shows "This comment no longer exists." (the existing `comments.stale` string, `i18n/en.ts:909`). Nothing is applied: `transform` reads every ref before building any command (`actions/comments.py:307-310`), so a stale ref fails the whole step.
3. **Locked.** Locked comments are selectable but have no handles and do not move (`movable`/`resizable` false); Delete skips them silently, as the desktop.

### 3.5 Keyboard moves

The desktop has none (its arrows turn pages, `document_view.py:793-801`). The web adds them for keyboard users (WCAG 2.1.1): with a comment selected and focus on its handle (section 5), **arrows move 1 pt, Shift+arrows 10 pt; Alt+arrows resize the bottom-right corner by the same steps**. Each press is an `annotations.transform`. So that holding an arrow is one undo step, `TransformAnnotations` gains `merge_key: str = ""`, passed to each `UpdateAnnotationCommand` (about 4 lines); the web sends `nudge:<page>:<name>` for a single comment. `MacroCommand` does not merge, so a nudge of several comments is one step per press (acceptable; Question 4). Presses are queued so only one call is in flight; a stale reply drops the queue.

## 4. The note popup

Port of `ui/view/note_popup.py`, as a non-modal popover anchored beside the note's icon (12 px offset, as `main_window.py:1568`), one at a time (`:1565-1566`):

- Header: author ("Unknown" when empty) and the modified or created date, formatted with the app's date helper.
- A textarea with the note's text, read-only when locked. The text is saved on close if it changed, with `annotations.set_text` and the label "Edit Note" (`note_popup.py:79-87`; `SetAnnotationText.label`, `actions/comments.py:180-183`).
- The replies (author: text), read from the `comments.page` thread, and a one-line reply box: Enter posts with `annotations.reply` and the author from preferences (W7.1b's `edits.ts` already wraps the call).
- A Close button; Escape closes (and saves); a click outside closes (and saves). Focus moves into the textarea on open and back to the note's handle on close.
- Text that came from the document is shown as text, never as HTML.

The note form used at creation (`CommentLayer.tsx:88-110`) stays as it is; the popup is for existing notes.

## 5. Keyboard use and screen readers

**Tools from the keyboard.** Each comment tool's page layer is focusable (`role="application"` with a label, as `edit/ShapeLayer.tsx:108-118`). Enter or Space places the tool's default comment centred on the current page (`centredGesture`, `edit/shapes.ts:110-120`): a note, a 100×60 box for rectangle, oval and text box, a 100 pt line or arrow, a callout with its tip 40 pt left of the box. Text tools then open their text form. Pen, polygon and polyline have no keyboard placement (a freehand path has no keyboard equivalent; Question 6). Markup tools need no extra path: keyboard text selection (W5.4) plus the ribbon button works. Escape cancels a gesture in progress, then turns the tool off.

**Comments on the page.** The page image is not readable, so each visible page gets a list of its comments as focusable elements positioned over their bounds (`role="group"` per page, labelled "Comments on page N"; each comment a `button` with the label "<type> by <author>: <first 80 characters of text>", plus "locked" when locked). One tab stop per page (roving `tabindex`): Tab reaches the page's comments, arrows inside the group are reserved for moving, so **Home/End and Ctrl+Up/Down step between comments** (Question 4). Enter selects (and opens a note's popup); Delete deletes; Escape returns focus to the page. These elements also carry the handles' focus for keyboard resize. Only pages in the render window get the list, so a long document does not build thousands of nodes.

**Announcements.** Add, move, resize and delete already end in a toast, which screen readers announce (`role="status"`, or `alert` for errors, `feedback/ToastRegion.tsx:76`); the toasts say what happened ("Comment added.", "Comment moved.", "Comment resized.", "Comment deleted."). New strings go through `t()` with keys in `i18n/en.ts`.

**Checks.** The axe spec (`e2e/features/axe.spec.ts`) gains a page with comments selected and the popup open; `forced-colours.spec.ts` covers the outline and handles (use `Highlight` and `CanvasText` system colours in forced-colours mode).

## 8. Risks

- **Capture-phase hit testing over the text layer**: a comment covering text blocks text selection on it. That is the desktop's behaviour; the Hand tool and the panel remain ways round it.
- **Pen strokes are big arguments**: 10 000 points is about 400 KB of JSON; the limit bounds it, and `simplify` runs in Python, so the stored stroke is the desktop's.
- **Two lists of the same comments** (panel and page cache): both are refreshed by the revision stream; the page cache is keyed by revision, so it can't be stale for hit testing.
