# W5.2 S3: adding bookmarks, and the view's vertical offset

Design note for slice S3 of W5.2 (PLAN.md: "pending: the web bookmark editing panel (#517's S2
and S3)"). S1 (#517) put the outline actions in the engine. S2 (#526, [W5.2-S2.md](W5.2-S2.md))
let the web Bookmarks panel rename, delete, move and re-target entries. S3 adds `outline.add`, and
makes both Add and Set to Current Page use the top of the current view instead of the page top.

Status: design only. Nothing here is implemented yet.

## 1. Scope

**In S3**

- Add a bookmark after the current row (as its next sibling), or as the current row's first child,
  from a key or the toolbar. In an empty outline, an Add button in the empty state.
- The destination is the page the reader is on, at the top of the current view (section 4).
- A default title built with `t()` ("Page {page}"), or the first line of the selected text (Q3).
- After the add, the new row is focused and its rename field opens with the title selected (Q2).
- Set to Current Page (S2) switches from `y: null` to the same view offset.
- Clicking or pressing Enter on a bookmark lands at its offset, not only at its page top (Q5): the
  outline entries gain a `top` field.
- `AddBookmark` gains an optional `expect_after`, so a stale panel gets `STALE_OBJECT` instead of
  adding in the wrong place (Q4).
- One Playwright feature spec for the bookmarks panel, covering the S2 edits and the S3 add.

**Not in S3**

- Drag and drop (a separate follow-up item).
- A global command (ribbon, command palette or app-wide shortcut) that adds a bookmark while the
  panel is closed (Q6).
- A horizontal offset or a zoom in the destination: x stays 0 and the zoom is not stored, as on the
  desktop.
- Changes to the desktop panel.

## 2. Contracts used (checked against the code)

`outline.add` (`src/pdfeditor/actions/outline.py`, `AddBookmark`), called through `actions.run`:

| key | type | meaning |
|---|---|---|
| `title` | string | stripped by the engine; 1 to 1000 characters after stripping |
| `page` | number | zero-based; must be in the document |
| `y` | number or null | visible-space points from the page top; null is the page top; must be finite |
| `after` | number or null | flat index of the entry to insert after; null appends at the top level |
| `as_child` | boolean | insert as the first child of `after` instead of its next sibling |
| `expect_after` | string or null | **new in S3**: the title of the entry at `after`, as shown; a mismatch raises `STALE_OBJECT` |

- The label is "Add Bookmark". It commits one `SetOutlineCommand`, so it is one undo step with a
  real inverse.
- `value` is the new entry's **flat index** after the add (`ActionResult[int]`). The panel focuses
  that row.
- A sibling add goes after the whole subtree of `after` (its children stay with it). A child add
  becomes the **first** child.
- `as_child` with `after: null` is `INVALID_ARGS`. The panel never sends it.
- An add never makes `executed: false` (the tree always changes).

The engine change for `expect_after` (about 6 lines): the field defaults to `None`, so the desktop
and S1's tests are unchanged. When `after` and `expect_after` are both given, `change` reads
`_path_at(tree, after)` and raises `StaleObject` when the title differs, as `_entry` does for the
other four actions.

The outline entries (`dto.OutlineEntry`, `webapi/session.py: outline_entries`) gain
`top: float | None`: `item.dest.point.y` when the destination has a point, else `None` (and `None`
whenever `page` is `None`). It is in visible-space points from the page top, the same space as the
action's `y`. `generated.ts` is regenerated with `python scripts/make_web_types.py`. This reads what
`document.outline()` already returns, so there is no new engine call.

## 3. Interaction design

### Toolbar and keys

S3 puts two buttons at the **start** of the S2 toolbar:

| Button | Key on the row | Sends | Disabled when |
|---|---|---|---|
| Add | Alt+Shift+N | `after: current`, `as_child: false` | an edit is running (`locked`) |
| Add Child | (none; see below) | `after: current`, `as_child: true` | locked; the current row's level is 32 or more |

- The buttons have `aria-keyshortcuts` (Add only: `"Alt+Shift+N"`) and the key in the tooltip, as
  the S2 buttons do.
- `treeAction` gets a new `add` kind. With Alt and Shift held (no Ctrl, no Meta), it matches the
  **physical** key: `code === 'KeyN'`. On macOS, Option+Shift+N gives `event.key === '˜'`, so
  `key` cannot be used. `KeyModifiers` gains an optional `code`.
- Why Alt+Shift+N (Q1): the S2 edit keys already live under Alt+Shift; N is free in the app; it
  needs no Insert key (missing on many laptops, and NVDA's and JAWS's modifier key); Ctrl+B is
  Firefox's bookmarks sidebar, and Ctrl+Shift+B is the browsers' bookmarks bar or library.
- Add Child has no key. The keyboard route is Add Child on the toolbar, or Alt+Shift+N followed
  by Alt+Shift+Right (which makes it the **last** child instead of the first). One fewer chord to
  learn, and no chord that could clash.
- Add Child is disabled at level 32 or deeper (`MAX_OUTLINE_DEPTH`), so the depth error is never
  reached from the panel in a normal outline. The engine still checks, and the S2 mapping
  (`error.REFUSED.outlineTooDeep`) covers it.

### Empty outline

The panel returns early today with `bookmarks.empty` when there are no entries. S3 keeps the
message, and when the outline is writable it adds a button below it: "Add Bookmark", which sends
`{ after: null, as_child: false }`. This is the desktop's empty state ("No bookmarks yet · Add
bookmark"). The key does not apply here, since there is no row to press it on.

### The new bookmark

- `page` and `y` come from the view's location (section 4), read at the moment of the click or
  key, not from a stale prop.
- The title: the first line of the selected text when there is one (Q3), else
  `t('bookmarks.newTitle', { page })` ("Page {page}"), where `page` is the page's label when the
  document has labels and the label is not empty, else the one-based page number. This is the
  desktop's rule (`add_bookmark` in `ui/panels/bookmarks.py`).
- The selected-text title: trimmed, first non-empty line, whitespace runs collapsed to one space,
  cut to 120 code points (`Array.from(text).slice(0, 120)`, so a surrogate pair is never split).
  These rules are a pure `defaultTitle(selected, label, pageNumber)` in `outlineEdit.ts`.
- The default title can never be empty or over 1000 characters, so the title `INVALID_ARGS` cannot
  come from an add. It can come only from a rename, which S2 already guards.

### After the add: focus and rename

1. The panel predicts the new outline with `applyAdd(entries, after, asChild, entry)` (pure,
   in `outlineEdit.ts`): it returns `{ entries, order, added }`, where `order[new] = old` and the
   new entry's `order` value is `-1` (so `remapExpanded` drops nothing and adds nothing for it).
   `added` is `subtreeEnd(e, after)` for a sibling, `after + 1` for a child, and `e.length` for an
   append.
2. For a child add, `after` is added to the predicted expanded set, so the new row is visible.
3. `runBookmarkEdit` now returns `{ outcome, value }` (S2's callers read `outcome`). On `done`, the
   panel sets `pendingFocus` to `{ index: value, rename: true }`. When `value` is not a number (it
   always is; this is defensive), it uses `added`.
4. The pending-focus effect (S2) runs after the reload. With `rename: true`, it makes the row
   current and calls `setEditing(index)` instead of focusing the row. The rename field focuses
   itself with the text selected (S2's `RenameField`).
5. The rename is S2's: Enter keeps the typed title (a second undo step, "Rename Bookmark"), and
   Escape or an unchanged title keeps the default title with no second step (Q2).

The S2 rule that a reload never steals focus still applies: if the user has moved the focus out of
the panel before the reply, nothing is focused and no rename field opens. The empty-state button
unmounts when the first entry arrives, so the focus is on `<body>` then, which the S2 effect
already treats as "still in the panel".

If the predicted `added` and the returned `value` differ, the returned value wins (the engine is
the truth) and the fingerprint check falls back to the file's flags, as for an S2 move.

## 4. The view offset

### What is read

The desktop's rule (`_current_destination` with `DocumentView.location()`): the **current page**
(the one the status bar shows), and how far the top of the viewport is below that page's top,
clamped to the page. When the viewport's top is above the page (the page starts lower down), the
offset is 0: the bookmark goes to the page top. This keeps the page in the toast and the title
the same as the status bar's, which a "page at the viewport top" rule would not.

### How it is read (no engine call)

A new pure helper in `web/app/src/view/layout.ts`:

```ts
// The place a bookmark should go to: the page, and how far the viewport's top is below the page's
// top, in the page's points. Null `top` is the page top. Null when the page is not laid out.
export function viewLocation(
  boxes: readonly PageBox[],
  heightPt: number,
  page: number,
  sceneTop: number,
): { page: number; top: number | null } | null;
```

- `box = boxes.find((b) => b.index === page)`; none gives `null`.
- `px = sceneTop - box.top`. When `px <= 0` or `box.height <= 0`, `top` is `null`.
- Otherwise `top = min(heightPt, px / box.height * heightPt)`, rounded to 0.01 pt. A fraction of
  the box, not `zoom * CSS_PX_PER_POINT`, so it holds for every layout and fit mode.
- `top < 1` counts as the page top (`null`): a jump lands at `box.top - gap/2`, so a reader who
  just went to a page gets `null`, the same as S2 sent (Q7).

`DocumentViewHandle` gains `location(): { page: number; top: number | null } | null`. The view
already keeps everything it needs in refs: `topPage.current` (the current page, zero-based; it is
set from `currentPage` despite its name), `boxesOnScreen.current`, `contentHeight.current`, and
`sizes`. It calls `viewLocation(boxesOnScreen.current, sizes[page].height,
topPage.current, viewportOf(scrollRef.current, contentHeight.current).top)`. `viewportOf` already
maps the scaled scroll space above 8 million CSS px to the scene, and the single-page layout keeps
the page's own index in its scene box, so the helper needs no case for either.

The web view has no view rotation, so the box's vertical axis is the page's visible y. If view
rotation comes to the web, this helper must apply it (a risk, section 10).

### Into the panel

`BookmarksPanelProps` gains:

- `location: () => { page: number; top: number | null } | null`, a function read at the moment of
  the edit (App passes `() => viewRef.current?.location() ?? null`). A function, not state, so the
  panel does not re-render on every scroll.
- `labels: readonly string[]` (App's `viewState.labels`), for the default title.
- `selectedText: () => string | null` (Q3), App reads `viewRef.current?.selectedText()` and returns
  the value only when its state is `ready`.

`currentPage` stays as the fallback when `location()` returns `null` (`{ page: currentPage,
top: null }`).

Set to Current Page sends `{ page, y: top }` from the same read. Its toast does not change.

### Going to a bookmark's offset

`choose(index)` passes the entry's `top` too: `onSelect(page, top)`. App's `goTo` for the panel
becomes the same path as `onLinkGoTo`: it records the jump and calls `scrollToPage(page, top ??
undefined)`, which already lands a point at the viewport top (W5.3). Without this, a bookmark added
at mid-page would go to the page top in the web app, and the offset would be visible only in other
readers.

## 5. The undo path

- `runBookmarkEdit` pushes the toast with `offerUndo('info', text, { rpc, handle, history:
  reply.state.history, onUndone: onHistoryStep })`. The text is
  `t('bookmarks.added', { title, page })`: "Added "{title}" for page {page}."
- The toast's Undo calls `actions.undo` with `expect_history`, then `onHistoryStep`, which bumps
  App's `structureRevision` (the change kind is `outline`). The panel reloads through its
  `revision` prop without remounting, as in S2. Ctrl+Z and the ribbon take the same path.
- Before the add, the expansion is saved under the current fingerprint; after it, the remapped
  expansion is saved under the predicted fingerprint (S2's mechanism). Undo and Redo find them.
- If the rename after an add is committed, there are two steps and two toasts. Ctrl+Z twice
  removes the bookmark. A toast's Undo is refused as stale (`toast.undo.stale`) when the history
  has moved past it, so the Add toast's Undo does nothing after a rename: the user undoes the
  rename first (the second toast). This is the existing W4.4b policy.

## 6. Accessibility

- **Roles and names.** The two buttons are in the S2 `role="toolbar"`. The empty-state button is
  a plain `<button>` under the status text. `aria-keyshortcuts="Alt+Shift+N"` on Add.
- **Focus.** After an add, the focus is in the new row's rename field (labelled "Bookmark title",
  S2), whose row is `aria-selected`, at its `aria-level`. Enter or Escape puts the focus on the row.
  So a screen reader announces the field, then the row with its level.
- **Announcement.** The Add toast is `role="status"`: "Added "Page 4" for page 4." It names the
  page, since the field's own announcement does not.
- **Disabled states.** Add Child at level 32 uses the native `disabled` attribute, as S2's edge
  buttons do, and the tooltip says why (`bookmarks.addChild.tooDeep`). While an edit runs, the
  buttons are `aria-disabled` (S2's `locked`) and the key is ignored, but still prevented.
- **Keys and the document.** The row handler calls `preventDefault()` on Alt+Shift+N even when it
  cannot act, so no document-level listener sees it (S2's rule).
- **Forced colours.** No new colours: the empty-state button uses the existing button styles.
- **Axe.** The feature spec runs axe on the panel with the rename field open on the new row, and
  on the empty state with its button.

## 7. Errors

| Code | When | Panel response |
|---|---|---|
| `STALE_OBJECT` | `expect_after` is not the title at `after` (the outline changed under the panel) | S2's path: info toast `bookmarks.stale`, reload, focus the same index clamped |
| `INVALID_ARGS` | page out of range, a non-finite `y`, `after` out of range, `as_child` with no `after`, an empty or too long title | `reportRpcError`. The panel prevents all of these, so it means a bug or a race (a page deleted between the read and the add) |
| `REFUSED`, `outline_too_deep` | a child add under an entry at the depth limit (when Add Child was not disabled, for example a file already deeper than 32) | `reportRpcError`, mapped by S2 to `error.REFUSED.outlineTooDeep` |
| `BUSY` | a job is running (`ensure_idle`) | `reportRpcError` (`error.BUSY`) |
| `NOT_SUPPORTED` | no `outline_write` (the buttons are not shown then) | `reportRpcError` |
| not an `RpcError` | | error toast `bookmarks.editFailed` |

`bookmarks.stale` says "nothing was edited", which is right for an add too.

## 10. Risks

- **The page rule.** The current page is the page at the viewport's middle. When the top of the
  view shows the end of the previous page, the bookmark goes to the current page's top, not to
  what the reader sees at the top. This is the desktop's rule and keeps the page number
  consistent; the guide says "the top of the current page, or where you have scrolled to on it".
- **View rotation.** If the web view gains rotation, `viewLocation` must map the box's axis to the
  page's visible y. A comment on the helper says so.
- **Zoom drift.** The offset is a fraction of the box, so it does not depend on the zoom. Rounding
  to 0.01 pt cannot move a landing point by a visible amount.
- **Duplicate titles.** `expect_after` cannot tell two entries with the same title apart if the
  list shifted between them (S2's risk). The add lands in a wrong but undoable place.
- **Two undo steps for add-then-rename.** Accepted (Q2). A single step needs a client-only
  "pending" row and an add that waits for the title, which is more code and a second source of
  truth for the tree.
- **Lossy rewrite.** The first add rewrites the whole outline, as every S2 edit does (S1's note).
- **Signed documents.** As S2: saved incrementally, no warning, matching the desktop.
- **Alt+Shift+N.** On Windows, Alt+Shift alone switches the keyboard layout, but only on press
  and release with no other key. Some screen readers may use the chord in browse mode; the tree
  role puts NVDA and JAWS in focus mode. The spec checks the key arrives in all three browsers.

## 13. Questions for the maintainer

1. **The add key.** Alt+Shift+N on the row, Insert, or Ctrl+B? **Recommended: Alt+Shift+N**, in the
   S2 Alt+Shift family, matched by physical key. Insert is missing on many laptops and is the screen
   readers' modifier key; Ctrl+B and Ctrl+Shift+B belong to the browsers.
2. **Open the rename field after an add?** **Recommended: yes**, with the default title selected,
   as Acrobat does. Escape keeps the default title. The cost is two undo steps when the user types a
   title. The alternative (no field; F2 to rename) is simpler but every new bookmark is then
   "Page N" until renamed.
3. **Title from the selected text?** The desktop does it. **Recommended: yes, the model selection
   only** (the Select tool; `selectedText()` in state `ready`). Under Hand, or while the page's text
   index is loading, the title is "Page N". About 10 lines.
4. **`expect_after` on `outline.add`?** Today the add has no staleness check. **Recommended: yes**,
   optional and defaulting to `None` (6 lines of Python plus tests), so the add is as safe as the
   other four actions.
5. **Honour the bookmark's offset when going to it?** It needs `top` on `OutlineEntry` (a webapi
   DTO field and regenerated types, no new engine call). **Recommended: yes, in S3**: otherwise the
   offset the slice adds is not visible in the web app, and the spec could not check it there.
6. **A global Add Bookmark command** (ribbon or palette, opening the panel)? The desktop has none
   (U3: "no Ctrl+B invented"). **Recommended: no** in S3; it needs the shared command registry and
   the desktop together.
7. **The page top: send `null` or `0`?** **Recommended: `null` under 1 pt**, so an add right after
   a jump writes the same destination S2 did, and S2's tests keep `y: null`. Any other place sends
   the number.
8. **PLAN.md.** S2's Q8 recommended ticking W5.2 after S3, with drag and drop as a separate item.
   **Recommended: tick W5.2 in the S3 PR** and add a new unticked follow-up line, "W5.2b Bookmarks:
   drag and drop", if you confirm. Otherwise S3 leaves W5.2 unticked with a partial note naming
   drag and drop as pending.
