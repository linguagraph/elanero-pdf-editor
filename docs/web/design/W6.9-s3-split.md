# W6.9 slice 3: landing the oversized persistence change (decision)

Status: decided on the owner's behalf on 2026-11-22. Decision only; no production code in this change.
Scope: issue #566, slice 3 of [W6.9-s3-s4-persistence-ui.md](W6.9-s3-s4-persistence-ui.md)
(the "design" below). The implementation is uncommitted in the worktree on branch
`phase-w-w6.9-s3-persist`.

## Decision

**Option (b), split, in three PRs rather than two.** The code stays as written (no smaller design),
but it lands as 3a storage and engine hook, 3b the library's start-up sync and add, and 3c removal and
other tabs. Each PR builds, passes its own tests and leaves the product working. Four fixes listed
below go in before the first commit of the PR that owns them.

Option (a) is refused: about 835 production lines is twice the plan's limit (plan.md, "≤ ~400
changed lines excluding tests") and twice the design's budget. Option (c) is refused: every piece
of the code is in the approved contract, and a smaller design would mean dropping owner decisions
(the broadcast, question 3; removal without residue, §3.5).

A two-PR split was checked and does not work: `fontLibrary.ts` alone is 512 lines, so whichever PR
holds it is over budget (store and hook in one PR, about 265 lines; library and wiring in the other,
about 540).

## Design deviations

### Accepted (the design is read as amended)

1. `bytes(id)` and `FontStore.read` return `BlobLike` rather than `Blob`. W6.8b needs only
   `arrayBuffer()` for its `FontFace`.
2. `LibraryFont` is `{id, name, size, kept, loaded, dto}` rather than "UploadedFontDto plus kept": a
   kept font the current engine has not loaded has no DTO, and slice 4's "not loaded" row needs
   `loaded`.
3. `FontStore.removeAll()` is added; design §3.5 removes the folder after the fonts and needed it.
4. `fontStore.ts` reuses three helpers newly exported from `autosaveStore.ts`. Moving them into
   `opfs.ts` is a later tidy-up, not worth the churn here.
5. `add` decides "already kept" from the library's list, not from an OPFS record lookup. A font
   another tab kept but this tab has not synced is written again: same bytes, and a writable commits
   whole on close, so nothing is lost; only its `added` time moves.
6. `storage` stays `unknown` until the first font is kept, when OPFS works. Slice 4 shows its hint
   only for `session`.
7. The `LOCAL_DATA_FOLDERS` membership test lives in `fontStore.test.ts`, not
   `clearLocalData.test.ts` (fix 4a adds the clear round trip there).
8. The limit is named `MAX_FONT_FILE_BYTES` (design: a hand copy of `MAX_FONT_BYTES`); same value
   and comment.

### Must be fixed before commit

1. **(3c) A tab that receives `removed` or `cleared` must not touch OPFS.** Design §3.6: the
   receiving tab removes the font from its own worker and its list. Today `removeOne(id, false)` and
   `removeEverything(false)` also call `store.remove` and the recursive `store.removeAll`. With three
   tabs this deletes data: A removes a font, C keeps it again at once, then B's late handler deletes
   C's files while C lists the font as kept. Only the tab that acts writes to the disk.
2. **(3a) A root that can't list its entries can't keep fonts.** Design §3.1: "A root without
   `keys` makes `list` return `[]` and `available` false." Today `available()` returns true when the
   `fonts` folder does not exist yet, and `write()` keeps a font that `list()` can never return, so
   the user is told the font was kept and loses it at the next reload. `available()` checks `keys`
   on the root (or the folder it creates), and `write()` returns `unsupported`, writing nothing,
   when it is missing.
3. **(3b) An id mismatch at start-up leaves no font in the engine.** Design §3.2 step 3 removes the
   font from OPFS; the worker still holds the changed bytes under the new id, unlisted but accepted
   by the `FILE` ref guard. Call `fonts.remove({id: reply.font.id})` unless that id is another
   listed font (residue rule, §3.5).
4. **Tests the design lists that are missing** (design §5; none of the existing tests is weakened or
   dropped):
   - a. (3a) `clearLocalData.test.ts`: a folder written by `createFontStore` is gone after
     `clearLocalData()`.
   - b. (3a) `fontStore.test.ts`: a write that throws `QuotaExceededError` gives `no-space`; a root
     without `createWritable` gives `unsupported`; a root without `keys` (no folder yet) gives
     `available() === false` and an `unsupported` write (fix 2).
   - c. (3b) `fontLibrary.test.ts`: `persist()` asked exactly once over two kept fonts; each of
     `INVALID_FONT`, `FONT_NOT_EMBEDDABLE`, `FILE_TOO_LARGE` drops the font with one notice, and each
     of `NOT_SUPPORTED`, `FONT_STORAGE_FULL`, `OUT_OF_MEMORY` keeps it with one notice (`it.each`);
     the store receives the `File` itself (the sent buffer is detached); `no-space` and `failed`
     give `notKept` with that reason; nothing kept means no engine call; a second `onReady` with the
     same client does not re-send; two operations started together run one after the other; the
     id-mismatch case asserts the engine no longer holds the mismatched id (fix 3).
   - d. (3c) `fontLibrary.test.ts`: a tab that receives `removed` or `cleared` leaves the disk
     untouched (fix 1), with a third tab that keeps the font again in between.

Line counts are measured as the design's are: production files, excluding tests. If 3b grows past
about 420 lines with its fixes, `useFontLibrary` (unused until slice 4) moves to slice 4.
