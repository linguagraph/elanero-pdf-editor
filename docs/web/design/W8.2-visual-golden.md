# W8.2 Visual golden tests for rendering

Status: proposed, for owner approval; no production code in this change.

Plan item: PLAN.md W8.2; docs/web/plan.md W8.2; W1.7 section 7 (web and desktop share the references in
`tests/golden/data/` and `tests/golden/compare.py`; a few UI screenshots on Chromium only).

## 1. What exists today

- `tests/golden/test_golden_render.py` renders 8 cases (text, images, vector art, annotations, rotated pages
  p1 and p4, CJK, layers) at scale 1.0 in RGB. It compares them with `tests/golden/data/<name>-p<page>.png`
  using `compare.py`, with `Tolerance(max_mean=1.5, max_bad_fraction=0.004)` and BAD_LEVEL 64. Failures write
  the actual image and an amplified diff image to `tests/golden/_actual/`.
- The same module already runs under Pyodide in Node in `web-pytest` (a required check). It is not marked
  desktop_only, numpy and pillow are in `versions.json` packageRoots, and the last budget run had 1065 passed
  and 0 failed. So the wasm MuPDF build already matches the desktop references at engine level.
- Desktop UI goldens: `tests/ui/test_ui_golden.py` writes to `tests/golden/ui/<platform>/<name>-<theme>@<n>x.png`
  with the same compare function.
- Web: there are no Playwright screenshots. `web-e2e.yml` runs nightly and is not required; the engine does not
  load in CI (#567).
- Gaps: no form, cropped or redaction cases. The web's own render path (`webapi.render.page` and `render.tile`:
  `view_matrix`, RGBA packing, tiling) is never compared with the references. The browser worker and canvas are
  not checked, and neither is the viewer's dark theme.
- Bug: a missing reference makes the test write one and skip (`or not ref_path.exists()`). That is a silent update.

## 2. Decisions

**D1. Three layers, one set of references for page pixels.**

| Layer | What it renders | Runs in | Required |
|---|---|---|---|
| L1 engine | `page.render` at scale 1.0 | test-windows (desktop) and web-pytest (Pyodide) | yes, both |
| L2 web API | `webapi.dispatch("render.page"/"render.tile")` | same two jobs | yes, both |
| L3 browser | worker render in Chromium, plus UI screenshots | web-e2e nightly | no |

Reason: L1 and L2 catch nearly every rendering regression in required jobs, with no browser and no #567
dependency. L3 adds only the browser transfer path and the chrome, which are both slower and flakier.

**D2. The golden set.** Pages come from fixtures made by `scripts/make_fixtures.py`. No PDF is committed, and
none is written by the tests.

| Case id | Fixture, page | Covers |
|---|---|---|
| text_multipage-p0 | existing | text |
| images-p0 | existing | images |
| vector_art-p0 | existing | vectors |
| annotations-p0 | existing | annotations |
| annotations_form-p0 | new | form widget with a value (appearance stream) |
| rotated_pages-p1, -p4 | existing | /Rotate |
| rotated_cropped-p1 | new | CropBox not at the origin, /Rotate 90 |
| rotated_cropped-p6 | new | negative MediaBox origin, /Rotate 180 |
| cjk_text-p0, layers-p0 | existing | fonts, optional content |
| sensitive-redacted-p0 | new | redaction applied in memory, then rendered |

The redaction case opens `sensitive`, adds a mark over the email line through the engine API that
`tests/engine/test_redaction.py` uses, applies it, and renders from memory. There is no save and no temporary
PDF. The reference proves the area is filled and nothing shows through.

Dark theme: page pixels do not depend on the theme (the CSS `data-theme`). Only the chrome changes, and night
reading is a CSS `invert(1)` filter (documentView.css). So the dark theme and night reading belong in the L3 UI
screenshots, not in the page references.

**D3. Storage.** Page references stay in `tests/golden/data/<case>.png`, which L1, L2 and L3 all read. Web UI
screenshots go to `tests/golden/web/linux/<name>-<theme>.png`, through Playwright's `snapshotPathTemplate`, next
to the desktop UI goldens in `tests/golden/ui/windows/`. PNGs only, saved optimized by `save_png`; each is under
about 100 KB. `_actual/` and Playwright output are gitignored and uploaded as CI artifacts on failure.

**D4. Tolerance.**
- Page pixels (L1, L2, L3 worker render): `compare.py`, unchanged at `max_mean=1.5` and `max_bad_fraction=0.004`.
  It already absorbs the difference between Windows and the Linux wasm build.
- L2 RGBA output is composited over white and turned into RGB before comparing.
- L2 view rotation 90: compared with `np.rot90` of the reference, same tolerance.
- L2 tiles: the stitched `render.tile` grid at a scale that spans at least 2x2 tiles is compared with
  `render.page` at that scale (a tile seam test, same tolerance). No extra PNG.
- A size change always fails (this already holds).
- UI screenshots: Playwright `toHaveScreenshot` with `maxDiffPixelRatio: 0.002` (W1.7 section 7), animations off,
  caret hidden, fixed viewport 1280x800 and deviceScaleFactor 1.

**D5. Web and desktop.** They share every page reference. A web difference is a bug or a MuPDF version skew, and
the failure message says so. There are no web page references. The chrome differs, so UI goldens are per surface
and platform: desktop Qt on Windows (existing), and web Chromium on Linux only (font rasterizing differs by OS, so
Firefox and WebKit take no screenshots).

**D6. Updates are deliberate, never silent.**
- A missing reference fails, with a message naming the command.
- Python: `uv run pytest tests/golden --update-goldens` (existing flag) on Windows. The PR body lists the changed
  PNGs and the reason, and attaches the before and after images or the CI diff artifact.
- Web UI: a `workflow_dispatch` input `update_snapshots` on web-e2e runs the visual spec with
  `--update-snapshots` and uploads the PNGs. A person commits them in a PR. The nightly run never updates.
- A collection test fails on orphan PNGs in `tests/golden/data` (no matching case) and on cases with no PNG.

**D7. CI.**
- L1 and L2 run in the existing required jobs: `test-windows` on every PR, and `web-tests / web-pytest` on web
  PRs. No new jobs.
- L3 runs in nightly `web-e2e` on Chromium and is not required, until #567 is fixed and it has been green for 14
  nightly runs. Making it required is then the owner's decision.
- Diff artifacts are kept 14 days.

## 3. Slices

**S1, engine set and strictness (about 120 lines plus 4 PNGs).**
- Add the 4 new cases to `CASES`, with the redaction case as its own helper.
- Missing reference fails; the orphan check.
- References taken on Windows with `--update-goldens`.
- Make sure web-pytest still passes under Pyodide. If the form or redaction case cannot run there, mark that single
  case, not the module.
- Done when: test-windows and web-pytest are green, and the PR body shows the 4 new images.

**S2, web API goldens (about 150 lines, no new PNGs).**
- `tests/golden/test_golden_webapi.py`: open each case through `webapi.dispatch`, then call `render.page` at
  scale_milli 1000 with rotation 0, compare to the reference.
- Rotation 90 on 3 cases, compared to the rotated reference.
- The tile seam test on text_multipage at scale_milli 3000.
- Add the shared `rgba_to_rgb` helper to `compare.py`.
- Runs on the host and under Pyodide.

**S3, browser worker render (about 180 lines).**
- `web/app/e2e/visual-render.spec.ts` in the harness: open each L1 fixture in the real worker, call `render.page`
  at scale_milli 1000, write the RGBA as PNG into `test-results/visual/`.
- A step in `web-e2e.yml` runs a host compare script, `tests/golden/compare_dir.py`, which reuses `compare()`
  against `tests/golden/data`, and uploads the diff images.
- Chromium only. Blocked on #567 for a green run; it can merge before then, like the other W8.1 specs, marked as
  pending in PLAN.md.

**S4, web UI screenshots (about 150 lines plus about 10 PNGs).**
- `visual-ui.spec.ts` against the app build: the start page, the document view with text_multipage, night reading
  on, the organizer and one dialog, each in light and dark.
- `snapshotPathTemplate` points to `tests/golden/web/linux/`.
- The update input on `web-e2e.yml` (D6).
- References come from the dispatch run, not from a developer machine.

Order: S1, then S2, are independent of #567 and give most of the value. S3 and S4 follow, and W8.2 is ticked after
a green nightly run of S3 and S4.

## 4. Risks

- A future MuPDF or Pyodide bump fails L1 under Pyodide only. That is intended: bump the pins together (decision 9),
  and never loosen the tolerance to hide it.
- Redaction output depends on the engine's fill colour option. Fix the options explicitly in the test.
- Chromium version drift moves the UI screenshots. The Playwright version is pinned in the lockfile, and an update
  goes through the dispatch path.

## 5. Owner questions

1. Should a missing reference fail even locally, not only in CI? Recommended: yes, always fail, and point to
   `--update-goldens`.
2. Should a PR that changes `tests/golden/**/*.png` need a label or a CI check? Recommended: not now; require a
   "Golden changes" section in the PR body, which the reviewer checks.
3. Where do the web UI screenshots live? Recommended: `tests/golden/web/linux/`, next to the desktop UI goldens,
   not Playwright's default folder.
4. When does L3 become required? Recommended: not by default; decide after #567 is fixed and 14 nightly runs are
   green.
5. Should night reading be checked by reading back the canvas pixels or only by screenshot? Recommended: only by
   screenshot (it is a CSS filter, and the page pixels are covered by L1 to L3).
