# W4.3b key probe: browser-reserved and second-group keys

Spike W4.3b (S5). It asks what each browser does with the keys the W1.6 table reserves, and with
the second group that the table may allow. Source: `web/app/e2e/keys.spec.ts`, config
`web/app/playwright.keys.config.ts`, manual workflow `.github/workflows/web-keys.yml` (Windows and
macOS runners). It is kept out of the default `npx playwright test` run (`testIgnore` in
`playwright.config.ts`).

## Method

- The production build (`vite build --base=/`, served by `vite preview` on port 4174), at the start
  page. No engine assets are needed.
- Each key runs in a fresh browser context. A capture-phase `window` listener records whether the
  key reached the page ("arrived"). A bubble-phase `window` listener, added after load, records
  `defaultPrevented`, which says whether the app took the key ("prevented").
- A closed page, a navigation or a new window counts as "taken by the browser".
- Ctrl is sent as Meta on macOS.
- Hard checks (the test fails without them): Ctrl+Shift+P arrives and opens the palette dialog;
  Alt+W, Alt+G, Alt+PgDn and Alt+PgUp arrive. Everything else is recorded only.
- The zoom keys (Ctrl+0, Ctrl+=, Ctrl+-) also record `visualViewport.scale` and
  `devicePixelRatio` before and after.

**Limit.** Playwright sends synthetic input, which can bypass a browser's own accelerators. So
"arrived" shows the key reached the page under synthetic input. It does not show what a real
keyboard delivers. The W1.6 reserved table stays policy whatever this run says.

## Results (local run, Windows 11, Chromium, Firefox and WebKit)

Every key arrived in every browser, except the one noted. "Prevented" is whether the app called
`preventDefault`. Chromium and Firefox gave identical results.

| Key | Group | Chromium | Firefox | WebKit |
|---|---|---|---|---|
| Ctrl+W, Ctrl+F4, Ctrl+Tab, Ctrl+Shift+Tab, Ctrl+N, Ctrl+Q, Ctrl+Shift+N, Ctrl+Shift+T, Ctrl+Shift+I, Ctrl+Shift+C | reserved | arrived, not prevented | same | same |
| Ctrl+1, Ctrl+2, Ctrl+6 | second | arrived, not prevented | same | same |
| Ctrl+0, Ctrl+=, Ctrl+- | second (zoom) | arrived, not prevented; scale 1, dpr 1 before and after | same | arrived, not prevented; scale 1, dpr 2 before and after |
| F6, Shift+F6 | second | arrived, not prevented | same | same |
| Ctrl+E | second | arrived, not prevented | same | same |
| Ctrl+K | second | arrived, **prevented** | same | same |
| Ctrl+D | second | arrived, not prevented | same | same |
| Ctrl+O | taken over | arrived, **prevented** | same | same |
| Ctrl+S, Ctrl+P, Ctrl+F | taken over | arrived, not prevented | same | same |
| Ctrl+Shift+P | taken over (hard) | arrived, prevented, palette open | same | **arrived, not prevented, palette not open** (hard check fails) |
| Alt+W, Alt+G, Alt+PgDn, Alt+PgUp | web replacement (hard) | arrived, not prevented | same | same |

Notes:

- The Ctrl+Shift+P failure in WebKit on Windows is recorded, not diagnosed. Ctrl+K and Ctrl+O reach
  the app's handler in WebKit, so the modifier path works. The cause is still open.
- The zoom keys did not change the viewport scale in any browser. Synthetic input cannot trigger
  browser zoom here, so this is not evidence that a browser keeps those keys.
- Chromium and Firefox show no key that the probe could not deliver, so the probe cannot separate
  the reserved keys from the second group. That is the limit above.
