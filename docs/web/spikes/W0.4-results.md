## Must fix before W3

1. **The whole MuPDF engine fails to import on the web** (`engine/mupdf/ocr.py` imports the excluded `ocr_worker` at module level, and `page.py` imports `ocr`). Task W2.2. This is the largest finding: 17 modules and 21 checks fail for this one line.
2. **`services/optimize.py` imports pikepdf at module level.** Task W2.2.
3. **Translation has no web transport.** The default `urllib` path fails in Pyodide and is reported as "offline". The web opener must be synchronous (see plan corrections). Task W2.4.
4. **TIFF on the web uses LZW, and deflate must never be tried.** `services/export/images.py` hardcodes `tiff_deflate` (lines 56 and 97). A failed deflate write aborts the Pyodide runtime on the next TIFF write, so the web writer takes its compression from the platform. LZW works, including a three-page file (probe b). Task W2.2.
5. **Secrets have no web store.** Task W2.3.
6. **Storage roots are MEMFS.** `data_dir()` and the autosave recovery directory are lost on reload. Task W2.3 (OPFS per plan).
7. **No OS fonts on the web.** Task W2.2 (flag) and W2.3 (font source), before W4.

Fine as they are: `threading.Lock`, `RLock` and `Event`; the render cache; the engine lock; `SnapshotCommand` on MEMFS; `DocumentSession` save to a path; `data_path()`; fontTools reads; Pillow PNG and JPEG; the text, Markdown, HTML and DOCX exporters; XLSX; `Document.optimize`.

## Plan corrections (applied to `docs/web/plan.md` except W2.2, see the note at the end; `PLAN.md` not edited, nothing ticked)

- **W2.2**: add the `ocr` import: "`engine/mupdf/ocr.py` imports `ocr_worker` (excluded) at module level, and `engine/mupdf/page.py` imports `ocr`, so the engine can't import on the web until the `ocr_worker` import moves into `text_layer()`." TIFF on the web uses LZW only: "deflate must never be tried on the web, because a failed deflate write aborts the Pyodide runtime" (no new `tiff` flag). Add the `optimize` split: "`linearize` and `_is_encrypted` import pikepdf lazily; `Document.optimize` works without it."
- **W2.3**: the storage items are: "`core/paths.data_dir()` needs an injected root (its default is MEMFS); the autosave recovery directory goes to OPFS; `services/fonts.system_font_dirs()` is empty on the web, so the font source is bundled or uploaded files; `core/secrets` gets an injectable store."
- **W2.4**: replace `pyodide.http.pyfetch` with a synchronous `js.XMLHttpRequest` opener that has the existing `Opener` signature (`Callable[[Request, float], Reply]`), injected via `TranslationConfig.opener` (update that field's "tests only" comment in W2.4). It omits `User-Agent` (a forbidden header in browsers), sets `timeout` and `withCredentials=false`, maps network and CORS errors to `OSError` (which gives `OfflineError`), and maps statuses to `Reply`. No client changes. The desktop keeps urllib. DeepL is dropped from the web if W0.3 finds it blocks CORS. It must be tested in a real browser. Rejected alternatives: an async path (too big: every client and `Translator` changes), a TypeScript-side fetch (restructures the clients), JSPI `run_sync` (not in all browsers), `pyodide-http` (an extra dependency, and it sends User-Agent), and `open_url` (GET only).
- **W2.5**: `core/jobs.py` and `core/render_cache.py` start no threads. They use `Event` and `Lock`, which work. The thread starter is `ui/jobs.py` (QThreadPool, excluded). So the inline runner replaces the `ui/jobs.py` threading, and `core/jobs.py` needs no `threads` flag.
- **W0.4 text (PLAN.md, line 148)**: "`core/jobs.py` and `core/render_cache.py` (threading; locks are fine, starting threads isn't)" should read "`ui/jobs.py` starts threads (QThreadPool, excluded); `core/jobs.py` and `core/render_cache.py` only use `Event` and `Lock`."
- **W2.6**: the import guard should cover the whole web set (95 modules), not "what webapi needs", and block `numpy` too. The audit shows one missed edge cascades to 17 modules, so a partial guard would miss it. The web set has 95 modules: `VERIFY_ASSETS.py` (a build-time script under `data/`) moved to the excluded set.
- **Decision 7 (plan)**: confirmed for `snapshot`, `data_path()` and the save path. Add: "the roots resolve to `/home/pyodide` (MEMFS), so they are not persistent without OPFS."
- **R4 row**: "`urllib` doesn't work in Pyodide" is precise as: the import works, `urlopen` fails with a network error, which the client reports as "offline".

## C6 (threads and processes): closed

- Where threads and processes are used in the web set: nowhere. The static scan finds no `Thread`, `Timer`, `multiprocessing`, `concurrent.futures` or `subprocess` in the 95 web modules.
- Where they are used: `ui/jobs.py` (QThreadPool, excluded) and `engine/mupdf/ocr_worker.py` (ProcessPoolExecutor, excluded, used only by `engine/mupdf/ocr.py`'s OCR path, which is off on the web).
- Runtime: `threading.Thread(...).start()` raises `RuntimeError: can't start new thread`. Locks and events work.
- Replacement: the inline job runner (W2.5), the web job worker that is terminated on cancel (W3.7), and the OCR capability off on the web.

## Deviations from the design note

1. **95 web modules, not 96.** `data/branding/elanero/VERIFY_ASSETS.py` is a build-time check of the branding assets, not app code. It is in `web/spike/web_package.py` `EXCLUDED` now.
2. **Subsetting.** Editing subsets fonts in MuPDF's `subset_fonts` during save. The test uses `Document.optimize(OptimizeOptions(subset_fonts=True))` after an installed font is embedded through `stamp_text`. No fontTools subset path exists in our code (fontTools is used to read and to rewrite for export).
3. **No export registry object.** The exporters are enumerated from `TextFormat`, `ImageFormat` and the export functions. `office.py` is excluded and not run.
4. **Jobs.** `core/jobs.py` has no runner. The check uses `CancelToken` and progress through `FontCatalog.scan`.
5. **Translation default transport** uses a dead local port (`MyMemoryTranslator` endpoint patched in the audit only), so the audit needs no network. The mocked-opener check builds each client with the default transport (`opener is None`), then sets the opener and calls it.
6. **One interpreter per pass**, with `pdfeditor.*` cleared from `sys.modules` between module imports (the design allowed this).
7. **Second pass (patched).** The one known blocker is applied to the audit's copy of the zip only, never to `src/`. Without it, 21 of the 25 failing checks stop at this one import error and never reach the code they test; the other four are findings in their own right. Both passes are reported.
8. **TIFF probes run in child processes.** A libtiff failure aborts the WebAssembly runtime, and in-process that ends the harness.
9. **The static scan doesn't read `sys.platform` branches.** Win32-only code shows as a module-level finding; each row above says which.
10. **Extra checks** beyond the design table: `data_path`, the default `data_dir`, Pillow codecs, `Document.optimize`, page render, `DocumentSession` from bytes, and the TIFF probes.
11. **Node runner.** `run_audit.mjs` repeats about 30 lines of the W0.1 runner's setup, because `run_engine_tests.mjs` exports only `prepare`. The W0.1 files are unchanged.
12. **Workflow.** The audit step sits after the host check and before the summary. It adds the zip and the audit input to the artifact, and this report too.
